# Плановые смены: почему их здесь больше нет

Здесь лежали тексты, которыми запускались плановые смены (Routines в
claude.ai/code). Разборов среди них больше нет, и вот почему.

## Что выяснилось

Плановая сессия стартует без единого внешнего инструмента. Её список —
`Bash`, `Write`, `Edit`, `Read`, `Glob`, `Grep`, `Agent`, и всё. Ни
`execute_sql`, ни GitHub, ни `add_repo`. Инструмент создания рутины
предупреждает об этом прямо:

> this trigger stores no MCP connectors, so the sessions it fires will run
> without connector (`mcp__<server>__*`) tools

Отсюда всё сразу: ноль строк в `razbors` и `shift_reports` за все прогоны —
не «мало», а ровно ноль, потому что писать было нечем; ни одного PR за трое
суток; и ни одной ветки, хотя смена трижды отработала по полчаса.

Три попытки починить это промптом провалились, и последняя — «пусть смена
сама достанет себе репозиторий через `add_repo`» — провалилась потому, что
`add_repo` там тоже нет. Это чинится настройкой рутины, а не текстом в ней,
и из сессии настройка недоступна: параметр `connectors` в организации
выключен, а пробросить свои инструмент не даёт.

## Где теперь живут разборы

В свипе на сервере: `lib/razbor/shift.ts` и `lib/razbor/shift-run.ts`,
вызов — из `app/api/reminders/sweep/route.ts`. Там рядом ключ модели, база и
тот же аудитор, которым пользуется публичная страница. Смена сама смотрит на
часы: раз в сутки, в 08:03 по Ташкенту.

Готовые разборы ждут человека в панели, разделе «Разборы». Публикует
владелец: текст выходит под именем студии и называет чужую работу плохой
публично.

## Что осталось рутиной

`experiment-300-2000.md` — эксперимент «300 → 2000». Он в том же положении:
рутина без инструментов, и с 13 сентября в его ветке нет ни одного коммита.
Файл оставлен как есть, чтобы не потерять текст, но работать он не может,
пока эксперимент не переедет тем же путём или пока рутину не пересоздадут из
интерфейса claude.ai с приложенными коннекторами.

## Если рутину всё-таки заводят заново

Через интерфейс claude.ai (Routines), а не отсюда: только там к ней
прикладываются коннекторы и репозиторий. Проверить, что получилось, можно
одной строкой в первой же смене — если она дошла до базы, в `shift_reports`
появится запись.

И отдельно: голос у смены теперь есть независимо от инструментов. Отчитаться
можно голым `curl`-ом, он есть в любой оболочке:

```bash
curl -sS -X POST https://devuz.studio/api/shift/report \
  -H "x-devuz-shift: СЕКРЕТ" -H "content-type: application/json" \
  -d '{"shift":"razbor","body":"Вышло 2 из 3: …"}'
```

Секрет живёт в `/opt/devuz/.env` и в самой рутине; в репозиторий его не
кладём.
