## Шаг 0. Достань себе репозиторий

Плановая сессия стартует в ПУСТОЙ папке: `pwd` даёт `/home/user`, `git rev-parse` — `fatal: not a git repository`. Смены 16 и 17 сентября на этом и кончились: полчаса работы, ни ветки, ни строки. Поэтому первым делом — репозиторий.

    pwd; git -C /home/user/DevUZ-perfect- rev-parse --show-toplevel 2>&1 | tail -1

Если ответ не `/home/user/DevUZ-perfect-`, достань его:

1. Вызови инструмент `add_repo` (сервер claude-code-remote): owner `egeg23`, repo `DevUZ-perfect-`, access `push`. Не проверяй репозиторий заранее через curl или git ls-remote: приватный отвечает «404 Not Found» даже когда доступ есть, и ты решишь, что его нет.
2. Выполни команду клонирования, которую вернул `add_repo`, в `/home/user/DevUZ-perfect-`. Если он ответил, что доступ уже есть и прикладывать нечего, клонируй сам:

        git clone https://github.com/egeg23/DevUZ-perfect-.git /home/user/DevUZ-perfect-

3. Вызови `register_repo_root`: owner `egeg23`, repo `DevUZ-perfect-`, directory `/home/user/DevUZ-perfect-`. Без этого навыки и CLAUDE.md из репозитория не подхватятся.
4. Убедись, что получилось:

        cd /home/user/DevUZ-perfect- && git fetch origin main && ls .claude/skills/

Дальше все команды выполняются из `/home/user/DevUZ-perfect-`.

Если репозиторий не достался ни одним способом — смена окончена, но НЕ молча. Последним действием напиши строку и закончи:

    insert into shift_reports (shift, body) values ('razbor', 'Смена не началась: репозиторий недоступен. <дословно то, что ответил add_repo или git clone>');

Молчание — худший исход из всех: владелец два дня считал, что разборы идут.

## Шаг 2. Веди смену по `razbor-daily`

Три пары «ниша + город», три разных сайта, три статьи на двух языках, снимки «как есть» и «как сделали бы мы», один PR из `claude/razbor-daily` в main на все три (`mcp__github__create_pull_request`), зелёный CI, мерж (`mcp__github__merge_pull_request`), проверка `https://devuz.studio/api/health`.

Инструменты базы в этой сессии могут называться не `mcp__Supabase__…`, а `mcp__<uuid>__…`. Ищи их через ToolSearch по имени — `execute_sql`, `list_tables` — а не по префиксу. Они есть.

Главное, что не обсуждается:

- Красный CI не мержится. На сервер уезжает только main, и сломанный main — это лежащий сайт студии.
- Мержишь ТОЛЬКО свой PR со своими разборами. Чужие открытые PR не трогаешь.
- Каждое число в тексте — из брифа аудита. Не перезамеряй. Цена студии — из content/services.ts целиком, вместе с верхней границей срока.
- Заголовки находок переписываются под нишу. Дословно скопированные строки аудита одинаковы для всех сайтов.
- Потерянные обращения считает `forecast()` из lib/razbor/forecast.ts, результат кладётся в поле `lostPer100`.
- Три — потолок, а не норма. Два честных разбора лучше трёх, где третий натянут.
- Название и логотип разобранной компании на снимке остаться не должны. Открой PNG глазами.
- Ниши бери разные, города — Узбекистан вперёд.
- Госсайты, банки, клиники, аптеки, сайты своих клиентов и партнёров не разбираем.
- В main напрямую не пушим и историю чужих веток не переписываем.

Роботов звать руками не надо: выкатка сама пингует IndexNow. Google sitemap.xml перечитывает сам.

Отклонённые сайты записывай в таблицу `razbors` со статусом `rejected` и причиной, иначе через неделю вернёшься к ним снова.

## Шаг 3. Отчёт — последнее действие смены, при любом исходе

У тебя нет токена бота, поэтому владельцу ты пишешь не в Telegram, а строкой в таблицу `shift_reports` через `execute_sql`; бот на сервере доносит её владельцу за пять минут:

    insert into shift_reports (shift, body) values ('razbor', 'Вышло N из 3: <ссылки>. Если меньше трёх — почему, одной фразой.');

Смена без этой строки — провал, даже если разборы вышли: владелец не узнает. Пустая смена со строкой «не нашлось годных сайтов: проверил 12, причины в razbors» — честный результат. Пустая смена без строки — тишина, неотличимая от поломки; с 18 сентября за такую тишину звонит сторож на сервере, и владелец увидит «Смена разборов — молчит».

Если `execute_sql` не нашёлся никаким именем — напиши то же самое в описание PR и последней строкой своего ответа.

Смена заканчивается тем, что разборы открываются на devuz.studio и строка ушла в `shift_reports`, а не тем, что PR «почти готов».
