# «Сияние Севера» — рабочий сайт на сервере клиники

Сайт стоматологии, админка и вебхуки — один образ `ghcr.io/egeg23/syanie-app`.
Собирает GitHub (`.github/workflows/syanie-app.yml`), сервер клиники только
скачивает и запускает (`deploy/remote.sh`). Модели нет: на сайте и в
мессенджерах отвечают люди.

## Что в админке

`https://<домен>/admin` — вход по логину и паролю.

- **Сводка** — новые заявки, кто ждёт ответа, что осталось подключить.
- **Заявки** — запись с сайта, квиз, заявки из переписки. Статус
  («Подтверждена», «Пришёл», «Отменена») пациент видит у себя на сайте.
  Кнопка «Отправить в amoCRM» или сами, если включено.
- **Сообщения** — одно окно: чат сайта, Telegram-бот клиники и всё, что
  подключено в Wazzup (Instagram, WhatsApp, Telegram-аккаунт, ВКонтакте,
  Авито, MAX). Ответ уходит в тот же канал, откуда написал пациент.
- **Сайт** — любой сотрудник правит без программиста (п. 5 техзадания
  договора № 360): контакты, WhatsApp и Telegram, цены All-on-6, услуги и
  цены по перечню клиники, акции и подарки, врачей с фото, вопросы, отзывы,
  цифры, гарантии, сервис и тексты разделов. «Сохранить» — сайт сразу
  собран заново тем же `gen.mjs` (`renderLive`), «Вернуть как было» —
  значения из `data.mjs`. Правки — в базе (`site.edits`), фото —
  `/opt/syanie/data/uploads`, всё экранируется (`lib/site-content.mjs`).
- **Подключения** — только главный врач: поддомен и токен amoCRM, токен
  Telegram-бота, ключ Wazzup, номер счётчика Яндекс.Метрики и коды
  Вебмастера и Search Console. Рядом с каждым полем написано, где взять.
  Ключи лежат в базе зашифрованными (`APP_SECRET` из `.env` сервера).
- **Команда** — администраторы со своим входом; «Привязать мой Telegram»:
  заявки и сообщения приходят сотруднику в Telegram, ответ (Reply) на
  уведомление уходит пациенту.
- **История** — кто что сделал.

## Что попросить у клиники

1. **Сервер (VPS)** — Ubuntu 22.04/24.04 или Debian 12, от 1 ядра, 1 ГБ
   памяти, 10 ГБ диска. IP-адрес и вход по SSH под `root` (или
   пользователем с `sudo` без пароля) — по нашему ключу. **Сервер в
   России**: имена и телефоны пациентов — персональные данные граждан РФ,
   хранить их нужно в России (152-ФЗ, ст. 18, ч. 5).
2. **Домен** — запись `A` на IP сервера. Можно сначала поддомен для
   проверки (`new.syanie-sewera.ru`), потом основной. Открыты порты 80 и 443.
3. **Ключи** — вводит главный врач сам в «Подключениях» после входа:
   - amoCRM: поддомен и долгосрочный токен (amoCRM → «amoМаркет» → «···» →
     «Создать интеграцию» → «Внешняя интеграция» → «Ключи и доступы»);
   - Telegram: токен бота от @BotFather;
   - Wazzup: ключ API (личный кабинет → «Интеграции» → «API»). Подписка
     Wazzup платная, по тарифу клиники; мессенджеры подключаются в самом
     Wazzup, в разделе «Каналы».

## Первая выкатка (один раз)

1. Ключ для выкатки, на своём компьютере:
   `ssh-keygen -t ed25519 -f syanie_deploy -N "" -C syanie-deploy`
2. Открытую половину (`syanie_deploy.pub`) — на сервер клиники:
   `ssh-copy-id -i syanie_deploy.pub root@<IP>` (по паролю, который дала
   клиника) или клинике — в `~/.ssh/authorized_keys`.
3. GitHub → репозиторий → Settings → Secrets and variables → Actions:
   - секреты: `SYANIE_HOST` (IP), `SYANIE_USER` (`root`), `SYANIE_SSH_KEY`
     (весь файл `syanie_deploy`), `SYANIE_PORT` (если SSH не на 22),
     `SYANIE_SETUP_CODE` (придумайте: латиница, цифры, `_`, `-`);
   - переменная (Variables): `SYANIE_DOMAIN` — домен без `https://`.
4. Actions → «Сайт Сияние Севера: сервер клиники» → Run workflow.
   Скрипт сам ставит Docker, создаёт `/opt/syanie`, поднимает сайт и HTTPS
   (Caddy получает сертификат Let's Encrypt сам). Если 80/443 уже занимает
   nginx клиники, Caddy не ставится: nginx получает файл
   `/etc/nginx/conf.d/syanie.conf`, сертификат — certbot, если он есть.
5. `https://<домен>/admin` → «Первый вход»: код установки
   (`SYANIE_SETUP_CODE`), имя, логин и пароль главного врача. Дальше он сам
   заводит администраторов и вставляет ключи.

Потом каждое слияние в `main` с правкой `scripts/protos/syanie/**` или
`public/protos/syanie/**` выкатывается само. Не поднялся новый образ —
скрипт возвращает прошлый и задача красная.

Журнал задачи публичный (репозиторий открытый): ключи, код установки и
`.env` в него не печатаются.

## На сервере

- `/opt/syanie/.env` — `APP_SECRET` (ключ шифрования ключей интеграций) и
  `SETUP_CODE`. Создаётся на сервере при первой выкатке. Потеряли
  `APP_SECRET` — ключи интеграций придётся вставить заново, заявки целы.
- `/opt/syanie/data/syanie.db` — база (SQLite): заявки, переписка,
  сотрудники. Копия: `docker stop syanie-app && cp -a /opt/syanie/data
  /root/syanie-backup-$(date +%F) && docker start syanie-app`.
- Контейнеры: `syanie-app` (сайт, `127.0.0.1:3000`, 512 МБ), `syanie-caddy`
  (80/443, 128 МБ).

## Чем рабочий сайт отличается от макета

Собирается тем же `gen.mjs` с `SY_PROD=1` (страницы — в `site/`, в git их
нет):

- нет видео DevUz, блоков «Сейчас и станет», «Чего нет у клиник Томска»,
  «Стоимость» и условий макета; `index, follow` и canonical на домен;
- запись (с выбором услуги) и квиз с полем телефона уходят на сервер
  (`site/store-live.js`), статус заявки пациент видит у себя; ловушка
  `website` от ботов;
- кнопки WhatsApp и Telegram в контактах и подвале, если номер и ник заданы
  в «Сайте» (Telegram без ника — бот клиники, если подключён); Метрика и
  коды поисковиков — из «Подключений», политика ПД о Метрике пишет сама;
- чат — с администратором (`site/live-chat.js`), без демо-ответов;
- страница `/privacy` — как клиника хранит имя и телефон. Текст общий:
  **показать юристу клиники до запуска**.

Чего в рабочем сайте нет, хотя было в демо-панели макета: расписание врачей
и напоминания пациентам. Факты сайта — из `data.mjs`; «немецкие импланты»
там стоят по слову владельца DevUz, у клиники на сайте марки нет —
**подтвердить у клиники**.

## Локально

```bash
cd scripts/protos/syanie
SY_PROD=1 node gen.mjs
ln -sfn "$PWD/../../../public/protos" app/site/protos
cd app && DATA_DIR=/tmp/sy APP_SECRET=local-secret-0123456789 SETUP_CODE=1 node server.mjs
```

С правкой из админки: `RENDER_DIR=$PWD/..` (папка с `gen.mjs`).

Проверки — `tests/syanie-app.test.ts` (вход, заявка → amoCRM и Telegram,
одно окно сообщений, правка сайта из админки, Метрика, рабочий сайт без
частей макета, выкатка).
