# «Сияние Севера» — рабочий сайт на сервере клиники

Сайт стоматологии, админка и вебхуки — один образ `ghcr.io/egeg23/syanie-app`.
Собирает GitHub (`.github/workflows/syanie-app.yml`), сервер клиники только
скачивает и запускает (`deploy/remote.sh`). Модели нет: на сайте и в
мессенджерах отвечают люди.

## Что в админке

`https://<домен>/admin` — вход по логину и паролю.

- **Сводка** — новые заявки, кто ждёт ответа, что осталось подключить.
- **Заявки** — запись с сайта, квиз, заявки из переписки. Статус
  («Подтверждена», «Пришёл», «Отменена») пациент видит у себя на сайте.
  Кнопка «Отправить в amoCRM» или сами, если включено.
- **Сообщения** — одно окно: чат сайта, Telegram-бот клиники и всё, что
  подключено в Wazzup (Instagram, WhatsApp, Telegram-аккаунт, ВКонтакте,
  Авито, MAX). Ответ уходит в тот же канал, откуда написал пациент.
- **Сайт** — любой сотрудник правит без программиста (п. 5 техзадания
  договора № 360): контакты, WhatsApp и Telegram, цены All-on-6,
  прейскурант по разделам (страница «Цены» и страницы услуг), акции и
  подарки, врачей с фото, образованием и квалификацией, вопросы, отзывы,
  цифры, гарантии, сервис, сведения о клинике (ИНН, ОГРН, лицензия),
  контролирующие органы, документы клиники (PDF) и тексты разделов и
  первого экрана каждой страницы. «Сохранить» — сайт сразу
  собран заново тем же `gen.mjs` (`renderLive`), «Вернуть как было» —
  значения из `data.mjs`. Правки — в базе (`site.edits`), фото —
  `/opt/syanie/data/uploads`, всё экранируется (`lib/site-content.mjs`).
- **Подключения** — только главный врач: поддомен и токен amoCRM, токен
  Telegram-бота, ключ Wazzup, номер счётчика Яндекс.Метрики и коды
  Вебмастера и Search Console. Рядом с каждым полем написано, где взять.
  Ключи лежат в базе зашифрованными (`APP_SECRET` из `.env` сервера).
- **Команда** — администраторы со своим входом; «Привязать мой Telegram»:
  заявки и сообщения приходят сотруднику в Telegram, ответ (Reply) на
  уведомление уходит пациенту.
- **История** — кто что сделал.

## Что попросить у клиники

1. **Сервер (VPS)** — Ubuntu 22.04/24.04 или Debian 12, от 1 ядра, 1 ГБ
   памяти, 10 ГБ диска. IP-адрес и вход по SSH под `root` (или
   пользователем с `sudo` без пароля) — по нашему ключу. **Сервер в
   России**: имена и телефоны пациентов — персональные данные граждан РФ,
   хранить их нужно в России (152-ФЗ, ст. 18, ч. 5).
2. **Домен** — запись `A` на IP сервера. Можно сначала поддомен для
   проверки (`new.syanie-sewera.ru`), потом основной. Открыты порты 80 и 443.
3. **Ключи** — вводит главный врач сам в «Подключениях» после входа:
   - amoCRM: поддомен и долгосрочный токен (amoCRM → «amoМаркет» → «···» →
     «Создать интеграцию» → «Внешняя интеграция» → «Ключи и доступы»);
   - Telegram: токен бота от @BotFather;
   - Wazzup: ключ API (личный кабинет → «Интеграции» → «API»). Подписка
     Wazzup платная, по тарифу клиники; мессенджеры подключаются в самом
     Wazzup, в разделе «Каналы».

## Первая выкатка (один раз)

1. Вход на сервер для выкатки — ключ или пароль (как у CZECHFARM):
   - ключ (надёжнее): на своём компьютере
     `ssh-keygen -t ed25519 -f syanie_deploy -N "" -C syanie-deploy`, открытую
     половину (`syanie_deploy.pub`) — на сервер: `ssh-copy-id -i
     syanie_deploy.pub root@<IP>` или клинике — в `~/.ssh/authorized_keys`;
   - пароль: тот, что дала клиника, — в секрет `SYANIE_PASSWORD`. После
     первой выкатки пароль лучше сменить и заменить секрет, а потом
     перейти на ключ.
2. Домен — запись `A` в DNS на IP сервера. Сначала поддомен для проверки
   (например `new.<домен>` → IP), основной адрес и `www` — когда клиника
   скажет «переключаем». Записи `MX` (почта) не трогать.
3. GitHub → репозиторий → Settings → Secrets and variables → Actions:
   - секреты: `SYANIE_HOST` (IP), `SYANIE_USER` (`root`), `SYANIE_SSH_KEY`
     (весь файл `syanie_deploy`) или `SYANIE_PASSWORD`, `SYANIE_PORT` (если
     SSH не на 22), `SYANIE_SETUP_CODE` (придумайте: латиница, цифры, `_`,
     `-`);
   - переменные (Variables): `SYANIE_DOMAIN` — домен без `https://`;
     `SYANIE_APP_PORT` — только если порт 3000 на сервере занят.
4. Actions → «Сайт Сияние Севера: сервер клиники» → Run workflow.
   Скрипт сам ставит Docker, создаёт `/opt/syanie`, поднимает сайт и HTTPS
   (Caddy получает сертификат Let's Encrypt сам). Если 80/443 уже занимает
   nginx клиники, Caddy не ставится: nginx получает файл
   `/etc/nginx/conf.d/syanie.conf`, сертификат — certbot, если он есть.
5. `https://<домен>/admin` → «Первый вход»: код установки
   (`SYANIE_SETUP_CODE`), имя, логин и пароль главного врача. Дальше он сам
   заводит администраторов и вставляет ключи.

Потом каждое слияние в `main` с правкой `scripts/protos/syanie/**` или
`public/protos/syanie/**` выкатывается само. Не поднялся новый образ —
скрипт возвращает прошлый и задача красная.

Журнал задачи публичный (репозиторий открытый): ключи, пароль, код
установки и `.env` в него не печатаются. Скрипт открывает в файрволе
сервера (ufw или firewalld) только 80 и 443, если он включён; файрвол в
панели хостинга клиника открывает сама. `www.<домен>` Caddy переводит на
основной адрес.

Сайт многостраничный, как их прежний сайт на WordPress (владелец,
16.11.2026): главная All-on-6, «Услуги» и семь разделов услуг по адресам
прежнего сайта (`/implantatsiya-zubov`, `/protezirovanie-zubov`,
`/khirurgiya`, `/esteticheskaya-stomatologiya`, `/lechenie-zubov`,
`/professionalnaya-gigiena`, `/diagnostika-zubov`), «Цены», «Врачи», «О
клинике», «Отзывы», «Акции», «Контакты», «Сведения о медицинской
организации», политика и согласие на обработку персональных данных.
Содержимое — `pages.mjs` и `catalog.mjs`, каркас — `pageShell` в `gen.mjs`.
Старые адреса с «/» в конце ведут 301 на те же без неё, страница отдельной
услуги прежнего сайта — на свой раздел (`lib/old-urls.mjs`). Если в
Вебмастере всплывёт старый адрес, которого там нет, — строкой в `RULES`.
Товары взломанного магазина (адрес с номером из 6–7 цифр в конце) и
служебные адреса WordPress (`wp-content`, `wp-sitemap.xml`, лента) отвечают
410: поисковики выбрасывают их быстрее.

Закон и правила, которые держит сайт:

- **152-ФЗ**: согласие на обработку данных — отдельный документ
  (`/soglasie`), в записи, расчёте и чате — галочка, не отмеченная заранее;
  без неё заявку и сообщение не принимает ни сайт, ни сервер. Когда и на
  какую редакцию дано согласие — в заявке (`consent_at`, `consent_v`) и в
  переписке чата, видно в карточке заявки. Политика (`/privacy`) — цели,
  данные, основания, сроки, права, кому передаётся, трансграничная передача
  через Telegram, cookie. Яндекс Метрика включается только после
  «Разрешить» в окне о cookie.
- **Платные медуслуги** (постановление Правительства РФ № 736):
  «Сведения о медицинской организации» (`/svedeniya`) — юрлицо, лицензия,
  режим работы, врачи с образованием и квалификацией, цены, бесплатная
  помощь, контролирующие органы, документы.
- **Версия для слабовидящих** (ГОСТ Р 52872-2019): кнопка с глазом —
  крупный шрифт, три схемы цветов, без картинок, большой интервал.

Врачи — блок «Наши врачи» (на главной и первым экраном «Врачей»): четыре
врача в полный рост, нажатие — врач выходит из строя, рядом его карточка
(стаж, направления, образование, «Записаться к врачу»), остальные в тени;
нажатие в любом месте — врач разворачивается и уходит на место. Врача,
которого добавят в админке, сайт ставит в ряд его фотографией; рендер в
полный рост для него делаем мы (`FIGS` в `catalog.mjs`).

Что клинике заполнить в админке («Сайт»): цены в «Прейскуранте» (пустая
цена на сайте — «уточните у администратора»), образование и квалификацию
врачей, в «Сведениях о клинике» — дату регистрации, кем выдана лицензия и
перечень работ по ней, почту и ответственного за персональные данные; в
«Документах клиники» — выписку из реестра лицензий, правила внутреннего
распорядка и образец договора. Клинике самой: уведомление в Роскомнадзор об
обработке персональных данных и о трансграничной передаче (уведомления
сотрудникам в Telegram), приказ об ответственном за обработку данных.

Для поисковиков:

- `/sitemap.xml` — все страницы сайта, `lastmod` — день последней правки
  страницы (по её отпечатку: выкатка без правок дату не двигает, правка
  цены двигает только страницы, где эта цена есть), фото с подписями.
- `/robots.txt` — закрыты `/admin` и `/api/`, `Clean-param` для меток рекламы
  (`utm_*`, `yclid`, `gclid`…): Яндекс не считает такие адреса отдельными
  страницами.
- Разметка schema.org — клиника (адрес, часы, цены, врачи), сайт, вопросы с
  ответами. Превью ссылки — `og.jpg` 1200×630.
- `/sitemap-gone.xml` — 1 891 адрес товаров взломанного магазина
  (`lib/gone-urls.txt`) с датой переезда. В `robots.txt` её нет: один раз
  добавить в Search Console («Файлы Sitemap») и Вебмастер, чтобы роботы
  быстрее перепроверили эти адреса и увидели 410. Когда в Search Console
  «Страница удалена (410)» перестанет расти — карту можно убрать.
- Подтверждение прав в Вебмастере и Search Console файлом из корня
  (`yandex_<код>.html`, `google<код>.html`) — строкой в `lib/verify.mjs`, с
  тем текстом, что дал поисковик. Без выкатки — код мета-тега в админке
  («Подключения») или TXT-запись в DNS.
- Другие домены клиники — переменная `SYANIE_ALIASES` (по умолчанию прежний
  сайт на Tilda `syanie-sewera.ru` и `implantatsiya-zubov-all-on-4-tomsk.ru`
  с `www`): как только их A-запись смотрит на этот сервер, Caddy после
  следующей выкатки ведёт их 301 на основной адрес тем же путём, а страницы
  Tilda (`/all-on-4`, `/conf`, `/spasibo`) сайт ведёт на нужные страницы. Пока не
  смотрят — выкатка пишет «ещё не смотрят на сервер» и их не трогает.
- Прежние адреса сайта (`new.<домен>`, на который у Caddy уже был
  сертификат) ведут 301 на основной, пока их запись A смотрит на этот
  сервер: список `remote.sh` пишет в `/opt/syanie/caddy/redirect.caddy`.

## На сервере

- `/opt/syanie/.env` — `APP_SECRET` (ключ шифрования ключей интеграций) и
  `SETUP_CODE`. Создаётся на сервере при первой выкатке. Потеряли
  `APP_SECRET` — ключи интеграций придётся вставить заново, заявки целы.
- `/opt/syanie/data/syanie.db` — база (SQLite): заявки, переписка,
  сотрудники. Копия: `docker stop syanie-app && cp -a /opt/syanie/data
  /root/syanie-backup-$(date +%F) && docker start syanie-app`.
- Контейнеры: `syanie-app` (сайт, `127.0.0.1:3000`, 512 МБ), `syanie-caddy`
  (80/443, 128 МБ).

## Чем рабочий сайт отличается от макета

Собирается тем же `gen.mjs` с `SY_PROD=1` (страницы — в `site/`, в git их
нет):

- нет видео DevUz, блоков «Сейчас и станет», «Чего нет у клиник Томска»,
  «Стоимость» и условий макета; `index, follow` и canonical на домен;
- запись (с выбором услуги) и квиз с полем телефона уходят на сервер
  (`site/store-live.js`), статус заявки пациент видит у себя; ловушка
  `website` от ботов;
- кнопки WhatsApp и Telegram в контактах и подвале, если номер и ник заданы
  в «Сайте» (Telegram без ника — бот клиники, если подключён); Метрика и
  коды поисковиков — из «Подключений», политика ПД о Метрике пишет сама;
- чат — с администратором (`site/live-chat.js`), без демо-ответов;
- страница `/privacy` — как клиника хранит имя и телефон. Текст общий:
  **показать юристу клиники до запуска**.

Чего в рабочем сайте нет, хотя было в демо-панели макета: расписание врачей
и напоминания пациентам. Факты сайта — из `data.mjs`; «немецкие импланты»
там стоят по слову владельца DevUz, у клиники на сайте марки нет —
**подтвердить у клиники**.

## Локально

```bash
cd scripts/protos/syanie
SY_PROD=1 node gen.mjs
ln -sfn "$PWD/../../../public/protos" app/site/protos
cd app && DATA_DIR=/tmp/sy APP_SECRET=local-secret-0123456789 SETUP_CODE=1 node server.mjs
```

С правкой из админки: `RENDER_DIR=$PWD/..` (папка с `gen.mjs`).

Проверки — `tests/syanie-app.test.ts` (вход, заявка → amoCRM и Telegram,
одно окно сообщений, правка сайта из админки, Метрика, рабочий сайт без
частей макета, выкатка).
