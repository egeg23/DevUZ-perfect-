# CZECHFARM — боевой сайт на сервере компании

Сайт CZECHFARM alliance (ООО «MIR-PHARM UNITED»), его панель и Telegram-бот —
один образ `ghcr.io/egeg23/czechfarm-app`. Собирает GitHub
(`.github/workflows/czechfarm-app.yml`), сервер компании только скачивает и
запускает (`deploy/remote.sh`). Модели нет: бот отвечает текстами из панели.

Состав — по смете к договору № DU-2026-01 (`kp/czechfarm-smeta.html`), все 16
строк: 14 оплаченных и два подарка (Telegram-бот для клиентов и арабская версия).

## Что на сайте

Семь страниц макета и «Политика данных» на четырёх языках: русский (`/`),
узбекский (`/uz/`), английский (`/en/`), арабский (`/ar/`, справа налево).
Страницы — тот же `gen.mjs` макета с `CF_PROD=1`: без видео DevUz, условий
макета, демо-панели и блока цены. Макет (`content/proto-bundles/chechfarm.json`)
остаётся макетом.

- Формы обращений идут на сервер (`/api/lead`); номер обращения и ключ статуса
  браузер клиента помнит сам, «Мои обращения» на странице «Контакты»
  спрашивают статус у сервера (`/api/track`).
- Продукты, новости, контакты, заголовки страниц и счётчики сервер кладёт в
  страницу при отдаче (`K.live`, title и description) — правка в панели видна
  сразу.
- Арабский — словарь `ar.json` от английского текста; не хватает строки —
  сборка падает и пишет `ar-missing.json`. Зеркальные стили — `rtl.css`.
- Комната инвестора: `/room/<личная ссылка>` — документы PDF, каждое открытие
  в журнал. Документы лежат в `/opt/czechfarm/data/ir`, публичной ссылки нет.

## Что в панели

`https://<домен>/admin` — вход по логину и паролю. Роли: владелец, руководитель,
менеджер (менеджер не видит запросы инвесторов, комнату инвестора, заголовки
страниц и историю).

- **Сводка** — новые, без ответственного, за сутки и неделю, что осталось сделать.
- **Обращения** — первой строкой новое; статус (его видит клиент на сайте),
  ответственный («Взять себе», назначить), заметка, история, «Отправить в CRM»,
  ответ клиенту в Telegram, если он писал боту.
- **Продукты** и **Новости** — «Опубликовать» и «Снять», фото, инструкция PDF;
  новость пишется на каждом языке, нет перевода — показывается русский.
- **Комната инвестора** — документы и личные ссылки: выдать, скопировать,
  закрыть, журнал открытий.
- **Сайт и бот** — контакты (пустое не показывается), карта для встраивания,
  частые вопросы и тексты бота, заголовки страниц, Яндекс Метрика и коды
  Вебмастера и Search Console.
- **Подключения** — только владелец: токен Telegram-бота, amoCRM (поддомен и
  долгосрочный токен) или Bitrix24 (адрес входящего вебхука), «уходит в CRM
  само». Ключи в базе зашифрованы `APP_SECRET` из `.env` сервера.
- **Команда** — сотрудники, роли, какие темы обращений кому приходят в
  Telegram; «Привязать мой Telegram» в «Подключениях».
- **История** — кто что сделал.

## Кабинет партнёра и клиента

`/account` (и `/uz/account`, `/en/account`, `/ar/account`) — регистрация по
почте и паролю: «Партнёр» (производитель, дистрибьютор — кабинет на проверке,
команде уходит обращение, одобряют в «Партнёры и клиенты») или «Клиент»
(аптека, клиника, врач, покупатель — сразу). В кабинете — свои обращения со
статусом, новое обращение (подписывается кабинетом) и «Привязать Telegram»:
ссылка в бот, после неё человек получает рассылки своего сегмента. Кука
`cf_a` — HttpOnly, 90 дней; заблокированный выходит сразу. Код — `account.js`
макета и `lib/audience.mjs`.

## Рассылки в бот

Подписчик — каждый, кто сам писал боту (сотрудники не считаются). При
`/start` бот спрашивает «Я партнёр / Я клиент» — это сегмент рассылки;
у привязанного кабинета сегмент — из кабинета.

- **Из панели** — «Рассылки в бот» (руководитель и владелец): текст, фото,
  кому (всем, партнёрам, клиентам) с числом получателей, история с «дошло,
  заблокировали, не дошло», «Остановить».
- **С телефона** — владелец или руководитель с привязанным Telegram пишет
  боту `/рассылка`, присылает текст (или фото с подписью) и нажимает, кому.
- Уходит в фоне не быстрее 25 сообщений в секунду; кто заблокировал бота,
  больше не получает.

## Telegram

Один бот на двоих:

- **Команде** — каждое обращение приходит тем, кто привязал Telegram, с
  кнопкой «✋ Взял»: нажал — обращение его, у остальных карточка меняется на
  «Взял: имя». Ответ (Reply) на обращение из бота уходит клиенту.
- **Клиентам** (подарок) — `/start` и `/faq` показывают частые вопросы
  кнопками; похожий вопрос словами получает ответ из панели; остальное
  становится обращением «Telegram-бот», дописанное в течение недели
  прикладывается к нему же.

## Что попросить у компании

1. **Сервер (VPS)** — Ubuntu 22.04/24.04 или Debian 12, от 1 ядра, 1 ГБ
   памяти, 10 ГБ диска. IP-адрес и вход по SSH под `root` (или пользователем с
   `sudo` без пароля) — по нашему ключу. Персональные данные граждан
   Узбекистана хранятся на сервере в Узбекистане (Закон «О персональных
   данных», ст. 27¹) — лучше местный хостинг.
2. **Домен** — запись `A` на IP сервера. Открыты порты 80 и 443.
3. **Ключи** — вводит владелец сам в «Подключениях»: токен бота от @BotFather;
   amoCRM или Bitrix24 — что у них есть.
4. **Наполнение** — сотрудники сами: продукты с инструкциями, новости,
   контакты, документы для инвесторов. Медицинские тексты — после согласования
   с ответственным.

## Первая выкатка (один раз)

1. Ключ для выкатки, на своём компьютере:
   `ssh-keygen -t ed25519 -f czechfarm_deploy -N "" -C czechfarm-deploy`
2. Открытую половину (`czechfarm_deploy.pub`) — на сервер компании:
   `ssh-copy-id -i czechfarm_deploy.pub root@<IP>` или в `~/.ssh/authorized_keys`.
3. GitHub → репозиторий → Settings → Secrets and variables → Actions:
   - секреты: `CZECHFARM_HOST` (IP), `CZECHFARM_USER` (`root`),
     `CZECHFARM_SSH_KEY` (весь файл `czechfarm_deploy`), `CZECHFARM_PORT`
     (если SSH не на 22), `CZECHFARM_SETUP_CODE` (придумайте: латиница, цифры,
     `_`, `-`), `CZECHFARM_SCENE_KEY` — ключ кадров сцены первого экрана: тот же,
     что у макета, в хранилище секретов Supabase `app.SCENE_KEY_CHECHFARM`
     (без него первый экран — картинкой, сцена по прокрутке не играет);
   - переменные (Variables): `CZECHFARM_DOMAIN` — домен без `https://`;
     `CZECHFARM_APP_PORT` — если на сервере 3000 уже занят.
4. Actions → «Сайт CZECHFARM: сервер компании» → Run workflow. Скрипт сам
   ставит Docker, создаёт `/opt/czechfarm`, поднимает сайт и HTTPS (Caddy
   получает сертификат сам). Если 80/443 уже держит nginx компании, Caddy не
   ставится: nginx получает файл `/etc/nginx/conf.d/czechfarm.conf`,
   сертификат — certbot, если он есть.
5. `https://<домен>/admin` → «Первый вход»: код установки, имя, логин и пароль
   владельца. Дальше он сам заводит сотрудников и вставляет ключи.

Потом каждое слияние в `main` с правкой `scripts/protos/chechfarm/**` или
`public/protos/chechfarm/**` выкатывается само. Не поднялся новый образ —
скрипт возвращает прошлый и задача красная.

Журнал задачи публичный (репозиторий открытый): ключи, код установки и
`.env` в него не печатаются.

## На сервере

- `/opt/czechfarm/.env` — `APP_SECRET`, `SETUP_CODE`, `SCENE_KEY` (права 600).
- `/opt/czechfarm/data` — база `czechfarm.db`, `uploads/` (фото и инструкции
  продуктов, публичные), `ir/` (документы инвесторам, только по ссылке).
  Копию делать вместе с `.env`: без `APP_SECRET` ключи интеграций не открыть.
- Контейнеры `czechfarm-app` (512 МБ, одно ядро, `127.0.0.1:3000`) и
  `czechfarm-caddy`.

```
CF_PROD=1 node scripts/protos/chechfarm/gen.mjs

cd scripts/protos/chechfarm/app && DATA_DIR=/tmp/cf APP_SECRET=local-secret-123456 SETUP_CODE=local PORT=4850 node server.mjs
```
