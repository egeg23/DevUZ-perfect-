# REA — обратная разработка в сессии Claude Code

[REA (Reverse Engineer Anything)](https://github.com/morluto/rea), MIT, —
один MCP-сервер для разбора того, к чему нет исходников. Что умеет:

- программы и библиотеки — через Ghidra: псевдокод, ассемблер, строки,
  вызовы, ссылки;
- приложения на JavaScript и Electron, .NET-сборки, Android-приложения,
  Flutter, прошивки;
- сайты: структура, скрипты, сеть, снимки экрана; записи трафика HAR и pcap.

Каждый вывод — с доказательствами и тем, чего REA не знает. Навык
`reverse-engineer-anything` подсказывает сессии порядок работы.

Для чего нам: понять, как устроена функция в чужом приложении, и сделать
такую же у себя; разобрать старое приложение клиента без исходников;
проверить подозрительный файл с сервера; сравнить две версии сборки.

## Установка

```bash
bash scripts/rea/install.sh
```

Скрипт можно звать сколько угодно раз, готовое он пропускает. Что ставит:

1. Ghidra 12.1.3 в `/opt` (~570 МБ архив, ~900 МБ на диске). REA принимает
   Ghidra 12.1.x;
2. `rea-agents` 6.7.0 из npm (команда `rea`);
3. `rea setup --client claude_code`: сервер `rea` в `~/.claude.json` с
   `GHIDRA_INSTALL_DIR` и `JAVA_HOME`, навык в `~/.claude/skills`;
4. проверку без модели: `claude mcp get rea` — `Connected`, а
   `rea doctor` принимает Ghidra.

Нужны Node.js 22.19+, JDK 21+, unzip, `ps` из procps и Claude Code CLI. В
облачном контейнере всё это уже есть. Первая установка занимает около двух
минут, почти всё время уходит на скачивание Ghidra.

Для Android-приложений REA нужен ещё JADX, для прошивок — binwalk; ставятся
отдельно, когда понадобятся (`rea doctor --json` скажет, чего не хватает).

## Чтобы REA был в каждой сессии

Инструменты MCP подхватываются при старте сессии: в той, где запустили
скрипт, их ещё нет (навык и команда `rea` уже работают). Поэтому ставить
заранее — строкой в **Setup script** облачного окружения (меню окружения в
заголовке сессии → Edit → Setup script):

```bash
curl -fsSL https://raw.githubusercontent.com/egeg23/DevUZ-perfect-/main/scripts/rea/install.sh | bash
```

Лучше — в отдельном окружении для разбора: ночным сменам и макетам Ghidra не
нужна, а установка добавляет к старту около двух минут.

## Как пользоваться

Файл или папка должны лежать в контейнере сессии. Дальше обычными словами:

- «Разбери через REA, как в этом приложении устроен поиск, покажи
  доказательства и сделай похожее у нас»;
- «Что делает этот бинарник, куда он ходит в сеть?»;
- «Сравни две версии сборки: что поменялось?».

Из терминала то же самое: `rea analyze /путь/к/файлу --provider ghidra --json`.
