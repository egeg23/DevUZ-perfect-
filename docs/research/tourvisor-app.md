Метка «не подтверждено» стоит там, где источник найти не удалось. Чего нет в источнике, то не написано как факт.

## 1. Турвизор (tourvisor.ru) для турагентств

### Что Турвизор даёт агентству

- Продукты B2B: Tourvisor PRO (подборки, лента горящих, постинг в соцсети), модуль «Поиск туров» для сайта агентства, «продающие модули» (горящие, минимальные цены, слайдер, календарь), бесплатный сайт, CRM. Источник: https://tourvisor.ru (раздел b2b), https://tourvisor.ru/b2b/tariffs
- Тарифы (за месяц, цена зависит от срока оплаты; в рублях и тенге, в сумах цен нет):
  - PRO: 750 ₽ / 4 500 ₸ (при оплате на год 490 ₽), 1 пользователь, без модуля поиска и CRM;
  - «Стандарт»: 2 200 ₽ / 13 200 ₸ (на год 1 590 ₽), 5 пользователей, сайт + модуль «Поиск туров» + CRM;
  - «Все включено»: 3 600 ₽ / 21 600 ₸, 10 пользователей, плюс продающие модули;
  - «Премиум»: 5 990 ₽ / 35 940 ₸, 20 пользователей, плюс несколько офисов.
  - Бесплатно 3 000 поисковых запросов в день, сверх — 0,08 ₽ за запрос; бот в Telegram/мессенджерах +600 ₽/мес.
  - Источник: https://tourvisor.ru/b2b/tariffs
  - Соответствие четырёх колонок цен срокам (месяц / 3 мес. / полгода / год) — наш вывод по странице, на ней колонки не подписаны явно.
- Отдельно — платный API (XML-шлюзы), страница https://tourvisor.ru/b2b/ddapi:
  - «Поиск туров» — «данные от более 90 туроператоров с актуальными ценами», можно сделать свою форму поиска и мобильное приложение; **от 5 000 ₽/мес**;
  - «Горящие туры» — от 3 000 ₽/мес;
  - «Описание отелей» (описания, фото, координаты) — от 3 000 ₽/мес.
  - Условия доступа, документация и цены для Узбекистана на странице не описаны — **не подтверждено**, уточнять у Турвизора.
- На сайте tourvisor.ru есть выбор страны (Россия, Казахстан, Беларусь, Узбекистан, Кыргызстан); для Узбекистана указан тот же московский номер +7 (495) 215 14 73. Отдельного офиса или домена в Узбекистане не нашли: tourvisor.kz ведёт на tourvisor.ru, tourvisor.uz не открывается (DNS). Источник: https://tourvisor.ru/b2b/tariffs, проверка curl 14.10.2026.

### Методы API (XML/JSON)

Официальная документация закрыта (лежит в Google Docs у партнёров). Список методов подтверждён по исходникам открытой PHP-обёртки https://github.com/max-kut/tourvisor (последний коммит 12.07.2022; ссылки на Google Docs документацию — в docblock каждого класса). Базовый адрес — `http://tourvisor.ru/xml/`, авторизация — `authlogin` + `authpass` от личного кабинета tourvisor.ru, ответ `format=json` (по умолчанию XML).

| Метод | Что делает |
|---|---|
| `search.php` | Запускает поиск, возвращает `requestid`. Обязательные: `departure` (код города вылета), `country`. Ещё: `datefrom`/`dateto` (d.m.Y, диапазон не больше 14 дней), `nightsfrom`/`nightsto`, `adults`, `child` + `childage1..3`, `stars` + `starsbetter`, `meal` + `mealbetter`, `rating`, `hotels`, `hoteltypes`, `regions`, `subregions`, `operators`, `pricefrom`/`priceto`, `pricetype` (за номер / за человека), `currency` |
| `result.php` | Забирает результаты по `requestid` (поиск асинхронный: сначала search, потом опрос result) |
| `actualize.php` | **Актуализация тура** по `tourid`. Параметр `request`: 0 — система сама решает, идти ли к туроператору; 1 — всегда проверять цену в системе туроператора; 2 — брать из базы |
| `actdetail.php` | Детали актуализации по `tourid` (рейсы, состав цены — по названию; содержимое ответа в обёртке не описано) |
| `hotel.php` | Описание отеля по `hotelcode`: фото (`imgwidth`/`imgheight`), услуги, отзывы (`reviews=1`) |
| `list.php` | Справочники: `departure`, `country`, `region`, `subregion`, `meal`, `stars`, `hotel`, `operator`, `flydate` (даты вылета по `flydeparture` + `flycountry`) |
| `hottours.php` | Горящие туры (`city`, `items`, …) |

- Валюта в `search.php`/`actualize.php` по обёртке 2022 года: 0 — рубли, 1 — у.е. (USD или EUR, зависит от страны), 2 — бел. рубли, 3 — тенге. **Сумов в списке нет**; есть ли они сейчас — не подтверждено. Источник: `src/Requests/SearchRequest.php`, `ActualizeRequest.php` в https://github.com/max-kut/tourvisor
- `list.php` живой: без логина отвечает `Authorization Error` (проверка curl 14.10.2026, `https://tourvisor.ru/xml/list.php`).
- Есть ли в API метод бронирования — **не подтверждено**. В обёртке его нет. В скрипте модуля для сайтов есть адреса `sendrequest.php` (заявка), `modpay.php` (оплата в модуле), `cart2.php` (корзина), а в приложении Турвизора «можно купить тур онлайн» через партнёрские агентства (https://apps.apple.com/app/id1605969538). Как именно это работает и доступно ли агентствам Узбекистана — не подтверждено. Исходя из публичной картины: **Турвизор — витрина и поиск; бронь у туроператора агентство делает само** (в кабинете оператора), это надо подтвердить у Турвизора. Адреса модуля: https://tourvisor.ru/module/init.js → `//tourvisor.ru/module/v6.26.7/core.min.js`.

## 2. Битрикс24 REST

- **Сделка в нужную воронку и колонку**: `crm.deal.add` с `CATEGORY_ID` (ID воронки, ≥ 0; без него — общая воронка) и `STAGE_ID` (без него — первая стадия воронки). Список воронок — `crm.category.list` с `entityTypeId=2`; стадии — `crm.status.list` с `ENTITY_ID: "DEAL_STAGE"` (общая) или `"DEAL_STAGE_{categoryId}"`. В примере пара `CATEGORY_ID=1` + `STAGE_ID="C1:NEW"` — формат `C<id>:<код>` виден по примеру. Контакты — `CONTACT_IDS` (массив), `CONTACT_ID` устарел. Сам `crm.deal.add` помечен устаревшим, рекомендуют `crm.item.add`. Источник: https://apidocs.bitrix24.ru/api-reference/crm/deals/crm-deal-add.html
- **Контакт**: `crm.contact.add` (или `crm.item.add` с `entityTypeId=3`). Источник: там же (ссылка на `crm.item.list` с `entityTypeId=3`).
- **Смена стадии**: событие `ONCRMDEALUPDATE` присылает только `data[FIELDS][ID]`, плюс `event`, `ts`, `auth`. Чтобы узнать новую стадию, нужно самим вызвать `crm.deal.get` и сравнить `STAGE_ID` с сохранённым. Источник: https://apidocs.bitrix24.ru/api-reference/crm/deals/events/on-crm-deal-update.html
- **Исходящий вебхук vs приложение**: исходящий вебхук шлёт POST на ваш адрес при событии, в `auth` есть `application_token` — сверять с токеном из настроек вебхука, иначе запрос недоверенный. Адрес обработчика — публичный HTTPS, без самоподписанного сертификата; в демо-режиме исходящие вебхуки недоступны. Входящий вебхук вызывает методы с правами создавшего сотрудника. Приложение (локальное или OAuth) нужно, если ставить на много порталов, нужен интерфейс внутри Б24 или методы контекста приложения (`event.bind`, `placement.bind`). Источник: https://apidocs.bitrix24.com/local-integrations/local-webhooks.html
- **Файлы в сделке**:
  - пользовательское поле типа «файл» (`UF_CRM_…`): значение — `id`, `url`, `urlMachine`. Для скачивания сервером — `urlMachine` (в ней токен), `url` — только для браузера пользователя. `id` — это ID файла CRM, не Диска, в `disk.file.get` его не передавать;
  - файлы в комментарии таймлайна: объект `FILES`; ссылка `urlDownload` без REST-токена не годится для сервера — брать ID, вызывать `disk.file.get`, качать по `DOWNLOAD_URL`;
  - ссылки могут быть одноразовыми или с ограниченным сроком — при ошибке получить заново; ссылки не логировать и не отдавать в клиентское приложение.
  - Источник: https://apidocs.bitrix24.com/api-reference/files/how-to-download-files.html
- **Облако vs коробка**: для исходящего вебхука в коробочной версии нужна активная лицензия и сетевой доступ к обработчику. Источник: https://apidocs.bitrix24.com/local-integrations/local-webhooks.html. Другие отличия (версии модулей, доступность новых методов вроде `crm.item.*`) — не подтверждены источником, проверять на конкретной коробке.

## 3. Оплата в Узбекистане

### Click
- Для приёма оплат через приложение Click, my.click.uz, USSD и Telegram-бот биллинг поставщика реализует запросы **Prepare** и **Complete** (Shop API). Есть ещё Merchant API (разделы: запросы, Click Pass, фискализация), Split Shop, плагины CMS, мобильная интеграция, платежи в Telegram. Источник: https://docs.click.uz/ (содержание разделов сайт отдаёт скриптом, тексты разделов прочитать не удалось).
- Prepare — `action = 0`; подпись `sign_string` = MD5 от `click_trans_id + service_id + SECRET_KEY + merchant_trans_id + amount + action + sign_time`, время `YYYY-MM-DD HH:mm:ss`. Complete — `action = 1`, возвращает `merchant_prepare_id` из Prepare. Источник: https://docs.click.uz/en/?p=15 (по выдаче поиска), https://github.com/click-llc/click-integration-php. Точная формула подписи для Complete нами не прочитана — сверять в документации.
- Подключение: онлайн-регистрация и оферта на merchant.click.uz (по публикации 2020 года). Источник: https://www.spot.uz/ru/2020/07/09/click. Текущие тарифы и список документов — **не подтверждены**.

### Payme (Payme Business)
- Merchant API: JSON-RPC 2.0 по HTTPS POST, только именованные параметры, ответ всегда HTTP 200 (иначе ошибка -32400). Источник: https://developer.help.paycom.uz/protokol-merchant-api/
- Методы: `CheckPerformTransaction`, `CreateTransaction`, `PerformTransaction`, `CancelTransaction`, `CheckTransaction`, `GetStatement`, плюс `SetFiscalData`. Источник: https://developer.help.paycom.uz/metody-merchant-api/
- Авторизация входящих запросов Payme — заголовок `Authorization: Basic …`, логин всегда `Paycom`, пароль — ключ кассы. Источник: официальный шаблон https://github.com/PaycomUZ/paycom-integration-php-template (`Paycom/Merchant.php`, `paycom.config.sample.php`).
- Подключение: заявка на сайте Payme Business или через колл-центр 1350, после одобрения — договор; онлайн-контрактация; автоматическая фискализация. Источники: https://docs.tgshop.io/osnovnye-nastroiki/sposoby-oplaty/payme, https://www.spot.uz/ru/2022/06/10/payme-business. Комиссия — **не подтверждена** (нашли только акцию «0% на 6 месяцев» для новых офлайн-партнёров до 31.12.2023, https://www.spot.uz/ru/2023/11/28/payme/).

### Uzum Bank
- Портал разработчиков developer.uzumbank.uz: эквайринг карт (Uzum Checkout), QR и кассы, фискализация, Merchant API (банк сам вызывает ваш сервер: check, create, confirm, reverse, status; Basic-авторизация, суммы в тийинах). Подключение — через менеджера, не самостоятельно; нужен договор с юрлицом/ИП и счёт. Источники (вторичные): https://apis.io/providers/uzum/, https://github.com/shaxzodbek-uzb/pay-uz. Официальную документацию сами не открывали — **не подтверждено напрямую**.

### Карты Uzcard/Humo и Visa/Mastercard
- Octo (Ravnaq-bank / Octobank) — интернет-эквайринг Visa, Mastercard, Uzcard, Humo, есть API. В оферте Octobank: **3,5%** с платежа по Visa/Mastercard/UnionPay, **0,8%** по Uzcard/Humo. Документ может быть устаревшим. Источники: https://www.spot.uz/ru/2020/04/17/ravnaq-bank, https://octobank.uz/assets/components/table_07/oferta_torgovtsa_na_zaklyuchenie_dogovora.pdf
- ATMOS — заявлен партнёром Uzcard, Humo, Visa и Mastercard. Источник: https://www.spot.uz/ru/2025/12/23/atmos/
- Kapitalbank, Paylov, Multicard — **не проверяли**, данных нет.
- Как агентства берут оплату сейчас: FUN&SUN Uzbekistan — Payme, наличные USD и UZS, карты Visa, Mastercard, UzCard, Humo, рассрочка «уточняйте у менеджера»; Click и Uzum не указаны. Источник: https://funsun.uz/

### Правила магазинов приложений
- **Apple, 3.1.3(e)**: если приложение продаёт физические товары или услуги, которые потребляются вне приложения, нужно использовать **не** встроенные покупки, а другие способы (Apple Pay, ввод карты). Тур — такая услуга, значит Click/Payme/карта в приложении разрешены. Источник: https://developer.apple.com/app-store/review/guidelines/ (пункт 3.1.5 — про криптовалюты, к турам не относится).
- **Google Play**: биллинг Google не нужен для физических товаров и физических услуг («transportation services… airfare»). Источник: https://support.google.com/googleplay/android-developer/answer/9858738

## 4. Рассрочка, страховка, визы, трансферы

- **Uzum Nasiya**: более 5 000 партнёров по Узбекистану, товары и услуги; лимит Start до 5 млн сумов, Max до 20 млн сумов; цена — разовая наценка. Туры в статье не упомянуты. Источник: https://uzum.uz/media/kak-ustroen-servis-rassrochki-uzum-nasiya/
- **Alif Nasiya**: до 24 месяцев, без первого взноса, более 850 000 клиентов (2024–2025). Источник: https://www.it-park.uz/ru/itpark/news/alif-uzbekistan-privlek-5-mln-dlya-razvitiya-servisa-rassrochki-nasiya
- **Рассрочка именно на туры** встречается: Mobtrip.uz — «оплачивать тур сразу или в рассрочку» (https://apps.apple.com/mx/app/mobtrip/id6754286812); FUN&SUN Uzbekistan — «возможна оплата в рассрочку — уточняйте у менеджера» (https://funsun.uz/). **Через какой сервис (Uzum, Alif, банк) — не подтверждено.** Anorbank — не проверяли.
- **Страховка и трансфер**: у FUN&SUN Uzbekistan медстраховка и трансфер аэропорт–отель–аэропорт входят в стандартный пакет. Источник: https://funsun.uz/
- **Визы**: onlinetours.uz оформляет визы (есть оферта на туристические визы), трансферы входят в часть пакетов. Источник: https://onlinetours.uz/. Справка по безвизу для граждан Узбекистана (Турция, ОАЭ, Таиланд, Вьетнам — до 30 дней; Египет — виза по прилёту около $25) — https://funsun.uz/ (данные агентства, не МИД).

## 6. Вывод: что реально сделать и где риски

Реально:
1. **Поиск туров из Ташкента через Турвизор** — данные есть (код вылета 106, цены в USD/EUR). Для своего приложения нужен API «Поиск туров» (от 5 000 ₽/мес) + «Описание отелей» (от 3 000 ₽/мес), поток: `search.php` → опрос `result.php` → `hotel.php` → `actualize.php` перед заявкой.
2. **Заявка → сделка в Битрикс24** (`crm.contact.add` + `crm.deal.add` с `CATEGORY_ID`/`STAGE_ID`), смена стадии → исходящий вебхук `ONCRMDEALUPDATE` → `crm.deal.get` → пуш клиенту «статус заявки». Документы (ваучер, билеты) менеджер кладёт в файловое поле сделки, приложение получает их через сервер по `urlMachine`.
3. **Оплата Payme/Click/картой** внутри приложения — магазины это разрешают (Apple 3.1.3(e), Google — физические услуги).

Риски:
- **Турвизор не бронирует за агентство** (по публичным данным): после актуализации бронь у туроператора делает менеджер руками. Автоматической брони в макете не обещать.
- **API Турвизора для Узбекистана**: цены и договор в рублях/тенге, сумов в валютах API нет (по данным 2022 года); с кем заключать договор из Узбекистана — уточнять у Турвизора.
- **Покрытие операторов**: какие ташкентские операторы есть в Турвизоре по именам — не подтверждено; горящие туры показывают 11 направлений и минимум 7 операторов по Ташкенту.
- **Цены операторов в USD**, а Click/Payme/Uzcard принимают сумы — нужен курс и правило пересчёта.
- **Рассрочка на тур** — не стандартный продукт Uzum/Alif для турагентств; условия партнёрства — только через менеджеров сервисов.
- Комиссии Click, Payme, Uzum публично не найдены; единственная цифра — оферта Octobank (3,5% / 0,8%), может быть старой.
