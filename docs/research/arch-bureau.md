# Архитектурное бюро: разбор образцов для макета

Дата: 15.10.2026. Задача: демо-макет сайта-картинки для архитектурного бюро.
Ориентир клиента: https://yodezeen.com/ (минимализм, фото на весь экран,
плавные переходы, большое меню с фоном у каждого пункта, форма связи справа,
видео на главной и картинка вместо него на телефоне, GSAP, Three.js по желанию).
Наш главный приём: фотореалистичный пролёт камеры, отрендеренный в Blender и
прокручиваемый скроллом (последовательность кадров на canvas).

Всё ниже проверено по HTML и скриптам сайтов (curl и WebFetch), без платных
сервисов. Где сайт не открылся, так и написано.

## 1. yodezeen.com: что внутри

Стек: Nuxt (Vue), GSAP со ScrollTrigger, Lenis (плавный скролл), Swiper
(галереи), Lottie (мелкая анимация), Cloudflare. Three.js нет: слово «three»
в коде встречается только внутри Lottie (`threeDElements`). Картинки: 421
ссылка на `.webp` на главной, `sizes="100vw"`, CDN `cdn.yodezeen.com`.

Главная:
- Прелоадер с видео: `<video preload="none" muted playsinline poster=…png>`,
  два `<source>`: обычный (`1_…mp4`, 28,6 МБ) и для экранов до 1023px
  (`media="(max-width: 1023px)"`, `2_…mp4`, 13 МБ, вертикальный). То есть
  телефон получает отдельный, вдвое более лёгкий ролик, а пока видео не
  пошло, виден постер.
- Блок проектов («Stillstone»): **пролёт по скроллу кадрами на canvas**,
  ровно наш приём. Подробности из кода:
  - компьютер: 569 кадров JPEG 1920x1080, ~87 КБ кадр (`sequence/desk3/`);
  - телефон: 568 кадров JPEG 1080x1920, вертикальные, ~103 КБ кадр
    (`sequence/mob2/`), отдельный рендер под портрет;
  - в сумме около 50 МБ на компьютере и ~58 МБ на телефоне: тяжело;
  - кадры качает Web Worker (`/workers/image-worker.js`) пачками по 8,
    `fetch(url, {priority: "low"})`, отдаёт blob-URL в основной поток;
  - до загрузки виден первый кадр обычным `<picture>` с `fetchpriority="low"`;
  - кадр выбирает `gsap.fromTo(... {value: 0 → 568, scrub: true})` на
    ScrollTrigger от «top bottom» до «bottom top»;
  - рисование: `drawImage` с обрезкой «cover» под экран, canvas
    с учётом `devicePixelRatio`, контекст `{alpha: false}`, сглаживание
    «high» на компьютере и «low» на телефоне, на телефоне через
    промежуточный offscreen-canvas.
- Переход в проект с главной: GSAP-таймлайн, обложка проявляется по
  `opacity`, затем секция раскрывается через анимацию `mask-size`
  (маска растёт до экрана), 1-1,5 с, `power4.in`.
- Дальше: блок книги «MONOGRAF BOOK», контакты по городам.

Меню и шапка: сетка на 7 колонок, пункты капсом мелким кеглем, при наведении
сверху выезжает тонкая линия (`scaleX` от центра, 0,4 с). На телефоне
остаётся только центральная кнопка меню. Разделы: Projects, Services, About,
Career, Contact, отдельная страница «connect-us».

Проекты (`/projects`): фильтр-кнопки «all projects / architecture / interior
design / large scale», список карточек с большим фото и названием. Страница
проекта: блоки «Concept» и «Implementation» с анимацией появления заголовков
(`anim-title`, `anim-text`), галерея на Swiper с превью-миниатюрами и
полноэкранным просмотром, список команды, внизу крупное «Let's Talk».

## 2. Похожие сайты

**ERA, жилой комплекс (era.estate, студия Vide Infra).** Site of the Day на
Awwwards, FWA и CSSDA (по словам студии). Красиво: вступление с
3D-силуэтами зданий, «световые линии» вокруг макета, объёмная галерея,
3D-карта района, выбор квартир по 3D-модели. Технически: собственный JS,
переходы Barba, интро на canvas `id="v3d-container"` (так по умолчанию
называет контейнер Verge3D, движок на Three.js с экспортом из Blender;
вывод по имени, не проверен). Архитектура показана **последовательностью
кадров**: `data-plugin="sequence parallax"`, 149 кадров WebP 2440x2440 (с
прозрачностью, файлы `.png.webp`), 143-167 КБ кадр, около 22 МБ. Видео
грузится лениво через `data-src`. Берём: блок «здание крутится по скроллу»
из ~150 кадров и ленивые видео.

**LIKOVA, бизнес-центр (likova.space, Vide Infra).** Awwwards Site of the Day.
Красиво: стеклянный куб на вступлении, ступенчатые панели, которые
перетекают друг в друга при скролле, параллакс 3D-интерьеров, генплан как
3D-сцена. Технически: Barba, WebGL-фоны (`webglDark`, `webglWhite`),
`parallax`, `reveal`, 704 ссылки на WebP. Видео парами: `5.accessibility.mp4`
(1920x1080) и `5.accessibility-mobile.mp4` (1080x1920), `data-src` и
автоплей, когда блок в зоне видимости. Берём: отдельный вертикальный ролик
и рендер под телефон, а не обрезку горизонтального.

**BIG, Bjarke Ingels Group (big.dk).** Next.js, Barba, видео на Vimeo.
Красиво: строгий каталог, каждая карточка проекта с большой фотографией,
маленьким значком-логотипом проекта, названием и городом; меню-дерево
(Architecture, Interiors, Landscape, Planning, Products с подразделами)
и есть фильтр. Берём: значок-символ у каждого проекта и меню как фильтр
по типам работ.

**Snøhetta (snohetta.com).** Своя сборка, картинки грузятся лениво.
Красиво: одна строка о бюро вместо героя, карточки проектов с короткой
фразой («A journey through conservation»), значок горы на кнопках Menu и
Close. Отдельно: панель «Dark mode / Simplified / Low-res» для слабого
интернета. Берём: подпись проекта одной фразой и режим «лёгкие картинки».

**Averna Homes (avernahomes.com.au/the-process, студия The Start).**
WordPress, Barba, WebP. На Awwwards отмечен горизонтальным и плавным
скроллом на странице «The process». Берём: горизонтальную ленту этапов
работы бюро (эскиз, проект, стройка, сдача).

**Apple, страницы продуктов (эталон приёма).** Классика «кадры по скроллу на
canvas» (AirPods Pro и др.), разобрано в статье CSS-Tricks из источников.
Берём: схему «первый кадр картинкой, остальные догружаются, canvas рисует
ближайший готовый».

Не открылись: zaha-hadid.com (заглушка Cloudflare «Just a moment...»),
mvrdv.com (пустой каркас Angular, без JS содержимого не видно).

## 3. Как делают пролёт по скроллу

**Кадры на canvas (yodezeen, ERA, Apple).** Рендер в PNG, сжатие в WebP или
AVIF, скролл выбирает номер кадра, `drawImage` рисует его на canvas.
Плюсы: кадр точный при любой скорости и в обе стороны, одинаково везде,
включая iOS Safari. Минусы: вес и число запросов, нужна стратегия загрузки.
AVIF на 20-30% легче WebP, но декодируется дольше: на 150+ кадрах на
среднем телефоне это заметно, поэтому основной формат WebP.

**Видео, перематываемое скроллом (`video.currentTime`).** Один файл, просто.
Но обычный ролик хранит полный кадр раз в несколько секунд, остальные как
разницу: перемотка прыгает на ближайший опорный кадр и дёргается. Лечится
кодированием «каждый кадр опорный» (`ffmpeg -g 1` или `-x264-params
keyint=1`), но файл вырастает в разы и всё равно зависит от скорости
перемотки в браузере, на iOS хуже всего. Годится для фона, не для главного
приёма.

**WebGL в реальном времени (Three.js, Verge3D).** Камера летит по пути из
Blender, сцена рисуется в браузере. Плюсы: можно крутить, лёгкий старт.
Минусы: фотореализм Cycles в браузере не повторить без запекания света,
нужны glTF + Draco + KTX2, телефоны греются. Для демо за короткий срок
риск выше пользы. Three.js оставляем на мелочь (например, шум или
искажение при переходе), не на пролёт.

**Рекомендация для нашего макета:**
- Компьютер: 180 кадров (6 с при 30 к/с), 1920x1080, WebP качество 70-75,
  цель 70-110 КБ кадр, итого 13-19 МБ. Для экранов 2560+ не рендерить
  4K: canvas растянет 1920 с мягким сглаживанием, на интерьере не видно.
- Телефон: отдельная камера под портрет, 120 кадров (берём каждый второй
  из 240 или рендерим 120), 1080x1920 не нужно: 720x1280, WebP качество 65,
  35-50 КБ кадр, итого 4-6 МБ. Это в 10 раз легче, чем у yodezeen.
- Загрузка: первый кадр обычным `<img fetchpriority="high">` (это и есть
  картинка героя), затем каждый 6-й кадр, затем каждый 3-й, затем остальные:
  пролёт работает сразу, только грубее, и уплотняется. Качать пачками по
  6-8 в Web Worker или `fetch` с `priority: "low"`, декодировать через
  `createImageBitmap`, рисовать ближайший загруженный кадр.
- Скролл: GSAP ScrollTrigger `scrub: 0.5` (лёгкое сглаживание), секция
  `pin` на 300-400vh, Lenis для мягкости. Canvas `{alpha: false}`,
  размер с учётом `devicePixelRatio`, но не больше 2.
- Экономия трафика: на `saveData` или медленной сети (`navigator.connection`)
  и при `prefers-reduced-motion` вместо пролёта 5-6 ключевых кадров
  слайдами.
- Blender: Cycles, 1-2 прохода с шумодавом, один путь камеры с плавным
  ускорением в начале и конце, без резких поворотов (скролл их усиливает),
  размытие движения слабое или выключено: при медленном скролле оно
  выглядит как мыло. Кадры в PNG, сжатие `cwebp -q 72 -m 6` в Actions,
  не на сервере.

## 4. Что берём в макет

- Пролёт по скроллу кадрами на canvas: 180 кадров компьютер, 120 телефон,
  отдельный вертикальный рендер, догрузка «редкие кадры сначала».
- Видео на главной с `preload="none"`, постером и двумя `<source>`: лёгкий
  вертикальный ролик для экранов до 1023px, а на телефоне с экономией
  трафика только картинка.
- Шапка из мелких пунктов капсом с выезжающей линией при наведении; по
  кнопке меню полноэкранное меню крупным шрифтом, у каждого пункта свой
  фон-фото, сменяется плавно при наведении.
- Форма связи выезжает справа поверх затемнения, GSAP, 0,6-0,8 с,
  закрывается по Esc и клику мимо, фокус остаётся внутри формы.
- Переход из списка в проект: обложка растёт до экрана через маску
  (`mask-size` или `clip-path`), как у yodezeen.
- Список проектов с фильтром «Все / Архитектура / Интерьеры / Крупные»,
  у карточки одна фраза о проекте (Snøhetta) и значок типа (BIG).
- Страница проекта: «Идея» и «Реализация», галерея на весь экран с
  миниатюрами, команда, крупное «Обсудим проект» внизу.
- Горизонтальная лента этапов работы бюро (Averna).
- Плавный скролл Lenis и проявление заголовков по строкам; шапка макета
  прячется при прокрутке и возвращается через 3 секунды (правило студии).
- Без Three.js в первой версии: всё «объёмное» делает рендер Blender.
