# Metiz Stroy — внутренняя заметка (полная техверсия)

Клиент: Metiz Stroy, Ташкент. Продажа и аренда спецтехники: башенные краны,
фасадные люльки, строительные подъёмники, самоходные коленчатые подъёмники,
грузовые лифты, запчасти. Есть свой айтишник и встроенный в сайт кабинет
(ERP/CRM на платформе Zelunt).

Аудит снят **пассивно**, как обычный посетитель и поисковик: обычные GET к
публичным страницам, публичному API каталога, robots/sitemap, TLS-сертификаты,
заголовки ответа. Входа, подбора, сканеров уязвимостей, обращений в `ERP`/
`ManagerArea` **не было** — разрешения на проверку безопасности нет. Дата
съёма: 12.10.2026.

> Эта заметка — для нас. В отчёт клиенту (`kp/metizstroy-audit.html`) точные
> адреса, заголовки, имена тегов и эндпоинтов, пошаговые способы починки **не
> идут** — там только «что видим → чем грозит» и масштаб. Айтишник клиента не
> должен починить всё по нашему тексту.

## 0. Две живые копии сайта (корень всей картины)

На клиента работают **два разных сайта на двух доменах одновременно**:

| | `metizstroy.uz` (без дефиса) | `metiz-stroy.uz` (с дефисом) |
|---|---|---|
| Что это | новый сайт-витрина, SPA на Vite/React | старый сайт + кабинет на платформе **Zelunt** |
| Сервер | `nginx/1.24.0 (Ubuntu)` | `Microsoft-IIS/10.0` (ASP.NET MVC, `__VIEWSTATE`) |
| Корень | `GET /` → 200 (React-шелл) | `GET /` → 301 → `/ru/`, язык в пути `/ru/…`, `/uz/…` |
| Кабинет | — | `/ru/ManagerArea/…`, `/erp` (новый шлёт `/erp` в no-index) |
| В адресной строке у клиента | — | да, менеджеры и клиенты работают здесь |

Оба отвечают 200. Новый домен в `sitemap.xml` ссылается на свои URL
(`/site/ru/…`), **но картинки товаров в его API отдаются с СТАРОГО домена**
(`https://metiz-stroy.uz/file/db/…`). То есть новый сайт не самостоятелен:
упадёт старый — на витрине пропадут все фото.

`og:url` на новом домене = `https://metizstroy.uz/site/ru/`, при этом в
адресной строке живёт `metiz-stroy.uz`. Для поисковика это две competing
копии одного бизнеса — классическое размывание (cannibalization).

**Что делаем (для нас):** свести к одному каноническому домену. Решить с
айтишником, какой домен главный (похоже, цель — новый `metizstroy.uz`),
со старого поставить 301 на соответствующие URL нового, кабинет увести на
поддомен (`erp.metizstroy.uz` / `crm.…`) под `noindex`. Пока не сведено —
любые SEO-усилия делятся между двумя копиями.

## 1. Новый сайт `metizstroy.uz` — не рендерится для поисковика (главная SEO-дыра)

SPA отдаёт **один и тот же пустой шелл (3737 байт) на любой URL**, в том числе
боту:

- `GET /site/ru/catalog/` → тот же `index.html`, что и `/`.
- `GET /site/ru/product/40` под `User-Agent: Googlebot` → снова 3737 байт,
  `<div id="root"></div>`, и **те же статические мета-теги главной**:
  `<title>Спецтехника в Ташкенте и Узбекистане — METIZ STROY</title>`,
  общий `description`, `og:image = https://metizstroy.uz/metiz-stroy-logo.jpg`
  для всех товаров. Контента карточки в HTML нет.
- `title`, `canonical`, `hreflang`, товарные `description` и `og:image`
  проставляются **только из JS** (в бандле: `document.title=…`,
  `Wl("canonical",…)`, `Wl("alternate",…,"ru-UZ")`). Яндекс JS почти не
  исполняет; Google исполняет с задержкой и не всегда.

Факт индексации (`site:` в выдаче, 12.10.2026): по домену находится
практически **одна** страница нового домена (`/site/ru/`), а 3 из 4 проиндек-
сированных результатов — это **старый** `metiz-stroy.uz`. Все 468 URL из
sitemap нового домена для краулера выглядят дубликатами главной.

`sitemap.xml` (новый домен): 476 `<loc>`, из них 209 товаров × 2 языка,
25 категорий × 2, + статика. `hreflang` ru-UZ / uz-UZ / x-default проставлены
корректно в sitemap — но content-less страницы это не спасает.

**Что делаем:** SSR или пререндер (prerender/SSG) товарных и категорийных
страниц, чтобы бот получал готовый HTML с товарным `title`/`description`/
`og:image`/H1 и микроразметкой. Это работа их айтишника или наша посадочная
надстройка. Это и есть причина «нас плохо видно».

## 2. Старый сайт `metiz-stroy.uz` (Zelunt) — техническое SEO отсутствует

Публичная главная `/ru/`, 1 372 550 байт:

- `<title>Добро пожаловать</title>` — заглушка платформы, не о бизнесе.
- Нет `<meta name="description">`, нет `<h1>`, нет `canonical`, нет `hreflang`,
  нет `ld+json` (Organization/Product/LocalBusiness).
- H2: «Категории товаров», «Категории услуг», «Преимущества», «О нас», «Нам
  доверяют», «Отзывы» — нормальная структура, но без заголовков верхнего
  уровня и метаданных.
- **30 изображений вшиты как `data:image/*;base64` прямо в HTML ≈ 1,26 МБ** из
  1,37 МБ страницы. Их нельзя кэшировать и сжать как файлы, страница тяжёлая.
- `<img>` 48 шт., у **39 нет `alt`** (или `alt=""`).
- Формы через модал `zlntModal_Open(... Action?(a)=LeaveRequest ...)`.
- robots старого домена: только `User-agent: * / Allow: /` — **sitemap не
  указан**, ссылки на карту нет.

**Что делаем:** это платформенный Zelunt, глубоко не перепишем. Если старый
домен решено гасить (п.0) — не вкладываемся, ставим 301. Если оставлять —
прописать title/description/H1/canonical/hreflang/Schema и вынести base64 в
файлы (работа их айтишника или платформы Zelunt).

## 4. Надёжность и безопасность (только то, что видно снаружи)

- **Просроченный сертификат на `www.metiz-stroy.uz`:** presented cert =
  `CN=zelunt.com` (wildcard `*.zelunt.com`), `notAfter = Mar 2 17:58:45 2026
  GMT` — истёк более полугода назад. Любой, кто наберёт `www.` к домену с
  дефисом, получает предупреждение браузера о небезопасном соединении.
  (Остальные валидны: `metizstroy.uz` LE до 23.11.2026, `metiz-stroy.uz` LE
  до 18.12.2026.)
- **Заголовки безопасности на HTML нового сайта отсутствуют:** в ответе
  `GET https://metizstroy.uz/site/ru/` нет `Strict-Transport-Security`,
  `Content-Security-Policy`, `X-Frame-Options`/`frame-ancestors`,
  `Referrer-Policy`, `X-Content-Type-Options`. `Content-Type: text/html` —
  **без `charset`**. (На `/api/*` HSTS и `nosniff` при этом есть — то есть
  настроено непоследовательно.)
- **Весь внутренний API-контур виден в публичном JS-бандле** (`view-source`
  доступен любому). В `assets/index-*.js` перечислены, среди прочего:
  `/api/auth/login`, `/api/auth/me`, `/api/payments/import-debts`,
  `/api/payments/manual-debt`, `/api/payments/sync-overdue-calls`,
  `/api/managers`, `/api/managers/statistics`, `/api/employees`,
  `/api/finance-transactions`, `/api/customers`, `/api/deals`,
  `/api/ai-inbox/…`, `/api/call-tasks/generate-voice`,
  `/api/telegram-users`, `/api/documents`, `/api/stock/set-quantity`.
  Сама по себе карта ручек — не пробой (эндпоинты мы не дёргали), но она
  рисует злоумышленнику схему кабинета. Для клиентского отчёта — только
  «служебная кухня видна снаружи», без списка.
- **SPA отдаёт 200 на любой несуществующий путь** (`/nonexistent-page-xyz`
  → 200, тот же шелл) — нет честного 404. Для поиска это «мягкие 404».
- Старый сайт раскрывает платформу: `Server: Microsoft-IIS/10.0`,
  `__VIEWSTATE`, ссылки `/DXR.axd`, `/ru/PoweredByZelunt`, зависимость от
  `zelunt.com` (CSS/JS оттуда).
- Из заметок владельца (видео кабинета, сами мы туда не ходили): пункт меню
  **«Test» в боевом меню**, у части товаров непрофиль, широкие права
  галочками у ~6 менеджеров. Для клиентского отчёта — только мягко «в рабочем
  меню виден служебный/тестовый пункт».

**Что делаем:** перевыпуск/снятие www-сертификата (их айтишник, 10 минут),
набор заголовков безопасности + charset на nginx, честный 404, увод кабинета
на noindex-поддомен, уборка тестовых пунктов. Мы это можем взять в
сопровождение, но многое — их айтишник.

## 5. Скорость

- Новый SPA: главный JS-бандл `assets/index-Cok5z5Hs.js` = **697 987 байт
  (~682 КБ) и отдаётся БЕЗ сжатия** — на запрос с `Accept-Encoding: gzip,
  deflate, br` ответ приходит с `Content-Length: 697987`, без
  `Content-Encoding`, без `Vary`. С gzip/br это ужалось бы в ~4-5 раз.
  Для телефона на мобильном интернете в Ташкенте — ощутимая задержка первого
  экрана (контент появляется только после загрузки и исполнения всего JS).
- `GET /api/public-products/?lang=ru`: 197 КБ, TTFB ≈ 2,0 c, total ≈ 2,6 c —
  каталог тянется одним большим ответом без пагинации.
- Старый сайт `/ru/`: 1,37 МБ на главной из-за base64-картинок; TTFB ~1,3 c.

**Что делаем:** включить компрессию и кэш-заголовки на статику (nginx, их
айтишник), code-splitting бандла, пагинация/ленивая загрузка каталога,
вынести base64 в файлы на старом.

## 8. Доработки кабинета (их пример — в приоритете)

Опираемся на то, что студия уже умеет (`lib/admin`): свой Telegram-бот,
рассылки, касания с проверкой сайта по факту, отчёты в 18:00, движок первички.
Ничего нового обещать не нужно — всё это у нас работает.

Пример клиента — **напоминания о компании по базе ≈ 3 000 контактов**:
- Поздравления с праздниками Узбекистана (Новый год, 8 марта, Навруз, Рамазан
  и Курбан хайит — даты плавают, 9 мая, 1 сентября День независимости, День
  учителя, День Конституции), день рождения клиента, годовщина сотрудничества.
- Каналы: Telegram-бот, SMS (Eskiz / Playmobile), опционально WhatsApp
  Business.
- Текст по сегменту (VIP / клиент / потенциальный) и языку (ru/uz).
- Отписка в одно касание, тихие часы, лимит частоты, отчёт о доставке/ответах.

Доработки под их боли (а не общими словами):
- **Мягкая лестница напоминаний о долге** — у них 77 должников и долг порядка
  −1,3 млн $, это главная боль. Серия писем/сообщений по нарастающей, без
  давления, с фиксацией ответа менеджеру.
- Напоминание об **окончании аренды и продлении** (они сдают технику —
  прямой возврат выручки).
- Напоминание о **плановом обслуживании техники**.
- **Возврат «потенциальных»** (1 147 контактов) сезонной цепочкой.
- **Сезонные предложения перед стройсезоном**.
- **Запрос отзыва** после закрытой сделки (закрывает дыру с отзывами из п.6).
- **Заявки с сайта и входящие звонки сразу в Telegram менеджеру** + **отчёт
  руководителю в 18:00** (ровно то, что у нас уже есть).
- ИИ по месту: черновик ответа клиенту, разбор звонков (у них в кабинете уже
  есть `/api/ai-inbox`, `/api/call-tasks/generate-voice` — есть на что лечь).

**Как встраиваемся:** отдельный модуль рядом с их системой, через их API или
чтение базы по согласованию с их айтишником, **без переписывания их кабинета**.
У них ASP.NET/Zelunt — мы не лезем внутрь, работаем сбоку.
