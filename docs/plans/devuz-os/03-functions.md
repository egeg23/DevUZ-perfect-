# 3. Функции и сценарии

Группы — те же четырнадцать направлений, что на странице `/box`
(`content/box-copy.ts`, `box.scenarios.items`). Файл «87 функций» в
репозитории не нашёлся (см. CLAUDE.md), поэтому функции здесь собраны
заново по группам; список сверить с презентацией владельца.

Пометки происхождения:

- **[перенос]** — логика уже есть в коде студии, переносим (указан файл);
- **[открытое]** — берём открытую программу (указана лицензия);
- **[с нуля]** — пишем сами.

Пометки коробок: **Л** — Лайт, **П** — Про, **Д** — Джарвис, **ДМ** —
Джарвис Max. «Все» — работает на всех.

## Сценарии

### Группа 1. Свой чат-помощник для офиса

**С-01. Ответ по документам компании** (все отделы; все)
- Кто: сотрудник пишет в чат «Офиса» или боту: «Какой штраф по договору с
  „Альфа“ за просрочку?»
- Коробка: ищет по папкам, к которым у сотрудника есть доступ (bge-m3 →
  Qdrant → reranker), берёт 3–5 кусков, отвечает главной моделью со
  ссылками на документ и страницу.
- Выход: ответ с цитатой и ссылкой «открыть пункт 7.2». Нет в документах —
  «не нашёл», без выдумки.
- Откуда: подбор кусков — по образцу `pickChunks` в `staff-helper.ts`
  [перенос]; индексация — Docling (MIT) + bge-m3 [открытое]; права на
  папки [с нуля].

**С-02. Письмо, текст, перевод** (все; все)
- Сотрудник: «Напиши поставщику вежливо, что оплата задержится на неделю, по-узбекски».
- Коробка: `chat-uz` (лучшая по сравнению модель Qwen для узбекского),
  проверка: латиница без кириллицы, без длинных тире и штампов.
- Выход: текст в чат с кнопками «Короче», «Официальнее», «Копировать».
- Откуда: проверки `plain-text`, `translationProblems` [перенос].

**С-03. Новый сотрудник: «как у нас принято»** (HR, руководитель; все)
- Новичок спрашивает бота: «Как оформить возврат?»
- Коробка: ищет в разделе «Регламенты», отвечает по шагам, ≤ 500 знаков,
  вопросы о деньгах компании — только тем, кому положено по роли.
- Выход: ответ; вопросы новичков за день — сводкой руководителю (что
  дописать в регламент).
- Откуда: `staff-helper.ts` и `helper-stats-store.ts` [перенос].

### Группа 2. Клиенты и продажи

**С-04. Заявка из Instagram ночью** (продажи; все)
- Клиент пишет в Instagram в 23:40: «Сколько стоит чистка зубов?»
- Коробка: сообщение приходит через Wazzup в единое окно; ИИ-сотрудник
  отвечает по прайсу компании (не выдумывает цен), спрашивает имя и
  удобное время, заводит карточку, ставит задачу «перезвонить» на утро.
  Команде ночью не пишет — в 08:00 сводка «Ночью написали».
- Модели: `chat` (+ `chat-uz`, если клиент по-узбекски).
- Выход: карточка клиента, переписка, задача, утренняя сводка.
- Откуда: Wazzup и окно — `syanie/app/lib/wazzup.mjs` [перенос]; ход
  ИИ-менеджера — `lib/ai-staff/engine.ts` (вызов модели передаётся
  снаружи, переносится без переделки) [перенос]; ночная тишина — по
  образцу `messageWindow` [перенос].

**С-05. Клиент «дорого»** (продажи; все)
- Клиент отвечает «дорого».
- Коробка: распознаёт возражение кодом, подставляет готовый ответ
  компании (лесенка цен из настроек), модель молчит; менеджеру — кнопки
  «Ответы на возражения» в карточке.
- Откуда: `lib/admin/objections.ts`, `sales-after-reply.ts` [перенос].

**С-06. Передача менеджеру** (продажи; все)
- Клиент готов купить или просит позвонить.
- Коробка: карточка тому менеджеру, кто на месте (был активен 30 минут),
  через полчаса без ответа — следующему; три сгоревших подряд — вне
  очереди до конца дня, руководителю строка.
- Откуда: очередь тёплых лидов `lib/admin/lead-queue.ts` [перенос].

**С-07. Чат на сайте компании** (маркетинг; все)
- Клиент компании ставит на свой сайт строку скрипта из «Настроек».
- Коробка: виджет ходит в коробку через защищённый вход (Caddy, ключ
  виджета), отвечает так же, как в мессенджерах. Если коробка недоступна
  снаружи — форма заявки.
- Откуда: `lib/ai-staff/widget-script.ts` [перенос]; выход коробки в
  интернет — через Tailscale Funnel или туннель **[не проверено, выбрать]**.

**С-08. «Порядок в лидах»** (продажи, руководитель; все)
- По будням в 10:00 и 16:00 бот присылает менеджеру лиды без движения 7+
  дней с кнопками «🏆 / ❌ / ⏳».
- Выход: решение по каждому, «⏳» → задача со сроком; руководителю — кто
  не отвечает боту.
- Откуда: `lib/admin/lead-tidy.ts` [перенос].

**С-09. Отправка в amoCRM / Битрикс24** (продажи; все)
- У клиента уже есть amoCRM, переезжать не хочет.
- Коробка: заявка уходит в amoCRM сама или кнопкой; ИИ всё равно работает
  в коробке.
- Откуда: `syanie/app/lib/amo.mjs` [перенос]; Битрикс24 [с нуля].

### Группа 3. ИИ-звонки

**С-10. Входящий звонок 24/7: запись в клинику** (клиника, сервис; П, Д, ДМ)
- Пациент звонит на городской номер в 21:15.
- Коробка: SIP-линия оператора → Asterisk → агент голоса (LiveKit Agents
  или Pipecat): Whisper слушает, главная модель ведёт разговор по
  сценарию записи, синтез отвечает голосом; свободное время — из
  расписания «Офиса»; запись — в CRM, пациенту SMS/Telegram.
- Модели: `stt` (faster-whisper, потоковый), `chat` с инструментами
  «найти окно», «записать», `tts` (Piper — русский; узбекский — свой голос,
  см. раздел 5).
- Выход: запись в расписании, расшифровка и аудио в карточке, строка
  администратору утром.
- Ограничения: задержка ответа должна быть < ~1 с — на Лайт не обещаем;
  одновременных разговоров на Про — 2–4, на Джарвис — 10+ **[не проверено,
  замерить]**. Холодный обзвон роботом — НЕ делаем (закон).
- Откуда: Asterisk (GPLv2) [открытое], LiveKit Agents (Apache-2) /
  Pipecat (BSD-2) [открытое], сценарий и связка с CRM [с нуля].

**С-11. Разбор всех звонков за день** (продажи, руководитель; все)
- Ночью коробка расшифровывает все записи звонков (АТС клиента или наша),
  оценивает по листу компании (поздоровался, выяснил потребность, назвал
  цену, договорился о следующем шаге).
- Выход: в 09:00 руководителю — оценки по менеджерам, 3 худших звонка с
  местом, где потеряли клиента.
- Откуда: расшифровка — `voice-transcribe.py` [перенос], оценка [с нуля].

**С-12. Пропущенный звонок** (все; все)
- Никто не взял трубку.
- Коробка: через минуту — сообщение клиенту в Telegram/WhatsApp/SMS
  «Перезвоним в течение 15 минут», задача менеджеру с таймером.
- Откуда: [с нуля] на движке «когда → что».

### Группа 4. Голос и совещания

**С-13. Протокол совещания** (руководитель; все)
- Спикерфон из комплекта, кнопка «Записать» в панели или голосом.
- Коробка: запись → Whisper (с разделением говорящих — pyannote,
  **условия модели проверить**) → главная модель: итог, решения, задачи с
  ответственными и сроками.
- Выход: протокол в документы, задачи — людям в бот (с подтверждением
  ведущего).
- Откуда: [открытое] + задачи `lib/admin/tasks.ts` [перенос].

**С-14. Голосовое боту → задача** (все; все)
- Руководитель наговаривает боту: «Дине — подготовить КП для „Бетта“ к пятнице».
- Коробка: расшифровка, распознаёт задачу, исполнителя и срок, просит
  подтвердить кнопкой.
- Откуда: `lib/admin/voice-notes.ts` [перенос], разбор в задачу [с нуля].

**С-15. «Джарвис, что сегодня?»** (руководитель; П, Д, ДМ)
- Утром руководитель говорит в спикерфон «Джарвис…» (своё слово
  пробуждения — обучаем сами, готовые модели openWakeWord нельзя).
- Коробка: сводка голосом — новые заявки, деньги за вчера (только тем,
  кому положено), просроченные задачи, звонки, что требует внимания.
- Выход: 60–90 секунд голоса и та же сводка текстом в бот.
- Откуда: сводка — по образцу «Главной» `lib/admin/hq.ts` [перенос];
  слово пробуждения, голос [с нуля]. Имя «Джарвис» — см. риски в
  [07-name.md](07-name.md).

### Группа 5. Документы и бухгалтерия

**С-16. КП и счёт по одной фразе** (продажи; все)
- Менеджер: «КП для „Гамма“ на 3 позиции из прайса, скидка 5%».
- Коробка: позиции и цены — из прайса компании кодом (модель цен не
  придумывает), текст — моделью, документ на бланке компании → PDF.
- Выход: КП и счёт в карточке клиента, кнопка «Отправить в чат клиента».
- Откуда: состав и сумма кодом `mockup-plan.ts` (`compose`), бланк
  `kp/letterhead.*`, PDF `scripts/kp-pdf.mjs` [перенос].

**С-17. Договор из реквизитов в сообщении** (продажи, юрист; все)
- Клиент присылает реквизиты текстом или фото.
- Коробка: текст — разбор регулярными выражениями
  (`requisites-parse.ts`), фото — Qwen3-VL → тот же разбор; договор по
  шаблону, «чего не хватает» — до отправки.
- Откуда: [перенос] + зрение [открытое].

**С-18. Скан паспорта / счёта поставщика → в базу** (бухгалтерия, HR; все)
- Сотрудник фотографирует документ телефоном в бот.
- Коробка: Qwen3-VL (или PaddleOCR для таблиц) → поля → проверка кодом
  (ИНН 9 цифр, ПИНФЛ 14, суммы сходятся) → в Paperless-ngx с тегами.
- Выход: карточка документа, поля, исходник; паспортные данные — только
  ролям с правом.
- Откуда: Paperless-ngx (GPL-3, исходники в коробке) [открытое], проверки
  [с нуля].

**С-19. Проверка договора контрагента** (юрист; П, Д, ДМ)
- Юрист загружает договор от поставщика.
- Коробка: сравнивает с «эталоном» компании, выделяет рискованные пункты
  (штрафы, односторонний отказ, подсудность), пишет замечания на полях.
- Выход: документ с пометками и список «что предложить изменить». Пометка
  «не юридическое заключение».
- Откуда: [с нуля].

**С-20. Банковская выписка → сверка** (бухгалтерия; все)
- Бухгалтер загружает выписку (файл банка).
- Коробка: разбирает платежи, сопоставляет со счетами из «Офиса», ставит
  «оплачено», непонятные — списком.
- Откуда: разбор форматов банков Узбекистана [с нуля, форматы собрать].

**С-21. Поиск по архиву** (все; все)
- «Найди все договоры с „Дельта“ за 2025 с пролонгацией».
- Коробка: поиск по смыслу (Qdrant) + фильтры Paperless.
- Откуда: [открытое].

### Группа 6. Фото и картинки

**С-22. Карточки товаров** (розница, маркетинг; П медленно, Д, ДМ)
- Менеджер загружает 20 фото товара на столе.
- Коробка: убирает фон, ставит на фон в стиле магазина, делает 3 размера
  (маркетплейс, Instagram, сайт) — Qwen-Image-Edit через ComfyUI.
- Выход: папка картинок, ночью — если очередь занята.
- Ограничение: на Про (ROCm на gfx1151) скорость и стабильность
  **[не проверено]**, обещаем только Джарвис.
- Откуда: ComfyUI (GPL-3) + Qwen-Image (Apache-2) [открытое]; FLUX dev —
  нельзя.

**С-23. Баннер к акции** (маркетинг; П, Д, ДМ)
- «Баннер на 8 марта, скидка 20%, наши цвета».
- Коробка: картинка без текста моделью, текст и логотип накладываются кодом
  (модели плохо пишут буквы, особенно узбекские).
- Откуда: [открытое] + наложение [с нуля].

### Группа 7. Видео для соцсетей

**С-24. Ролик для Instagram по сценарию** (маркетинг; Д, ДМ)
- Маркетолог: «Ролик 20 секунд про акцию на имплантацию».
- Коробка: сценарий (главная модель) → кадры Wan 2.2 (или фото компании) →
  озвучка → субтитры → монтаж (FFmpeg) → публикация по расписанию.
- Выход: ролик 9:16 на согласование, после «Да» — в очередь публикаций.
- Ограничения: Wan 2.2 — минуты на секунды видео даже на RTX PRO 6000
  **[не проверено, замерить]**; только Джарвис.
- Откуда: Wan 2.2 (Apache-2), FFmpeg (LGPL/GPL — собрать без GPL-частей
  или отдельной программой) [открытое]; сборка и публикация [с нуля].

### Группа 8. Музыка и звук

**С-25. Голос автоответчика и озвучка** (маркетинг, администратор; все)
- «Озвучь: „Здравствуйте, вы позвонили в клинику…“»
- Коробка: Piper (быстро, русские голоса `dmitri`/`denis`, CC0) или
  CosyVoice 3 (живее, П и выше); узбекский — после записи своего голоса.
- Выход: WAV/MP3 в АТС или в ролик.
- Музыка: модель генерации музыки с коммерческой лицензией — **не
  выбрана, проверить**; до проверки — только библиотека свободной музыки.

### Группа 9. 3D-модели товаров

**С-26. 3D из фото** (розница, мебель; Д, ДМ)

- Коробка: объёмная модель (GLB) для сайта и презентации.
- Модели: Hunyuan3D — нельзя (не действует в ЕС/UK/KR). Нужна модель с

  До выбора — группа в статусе «позже».

### Группа 10. Код без программиста

**С-27. Страница записи по описанию** (маркетинг, владелец бизнеса; П, Д, ДМ)
- «Нужна страница: услуги, цены из прайса, форма записи, кнопка WhatsApp».
- Коробка: Qwen3-Coder пишет страницу по нашему шаблону, проверка кодом
  (без тире и штампов, форма ведёт в «Офис»), предпросмотр, «Опубликовать» —
  на домен клиента или страницей коробки.
- Откуда: проверки макетов `lib/proto/plain-text.ts`, `lib/proto/check.ts`
  [перенос], агент — OpenHands (MIT) [открытое], шаблоны [с нуля].

**С-28. Отчёт или таблица по описанию** (бухгалтерия, руководитель; все)
- «Таблица: выручка по врачам за месяц».
- Коробка: запрос к базе «Офиса» только на чтение и только в данных,
  которые видит этот человек; таблица → XLSX.

**С-31. Напоминания о сроках** (все; все)

**С-32. Агент в браузере: цены конкурентов** (розница; П, Д, ДМ)

## Что входит в первую версию (предложение)

Первые продажи держатся на том, что уже работает у студии и клиентов, —
остальное приходит обновлениями:

1. Чат-помощник с поиском по документам (С-01…С-03).
2. Клиенты и продажи: единое окно, ИИ-сотрудник, CRM, задачи (С-04…С-09).
3. Документы: КП, счёт, договор, сканы (С-16…С-18, С-21).
4. Голос: голосовые и протоколы (С-13, С-14).
5. Сама коробка целиком (С-41…С-44).
6. Пакет «Клиника» (С-35) — есть живой образец.

Во второй волне: звонки (С-10…С-12), «Джарвис» голосом, агенты, камеры.
В третьей: медиа (картинки, видео, 3D, музыка) — на Джарвисе.
