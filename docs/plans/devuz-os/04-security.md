# 4. Защита — мягкий вариант

Решение владельца: коробка защищена от подмены и копирования нашей
системы, но **не держит клиента в заложниках**. Замена деталей коробку не
блокирует, копия данных клиента доступна ему всегда, поддержку он
выключает кнопкой.

## Что защищаем и от кого

| Что | От чего | Чем |
|---|---|---|
| Наша система и приложения | подмена, «докрутка» без нас, копирование на другое железо | Secure Boot своими ключами, подписанные UKI, dm-verity, подписанные контейнеры |
| Данные клиента | украли коробку или диск | LUKS2, ключ запечатан в TPM |
| Офис клиента | флешка с вирусом, чужое устройство | USBGuard по белому списку, нет shell |
| Канал поддержки | наш доступ без ведома клиента | Headscale, кнопка, журнал, короткие сертификаты |
| Магазин функций | чужой код в коробке | только наши подписанные наборы |

Чего мягкий вариант **не** обещает: остановить человека с паяльником и
временем (снять чип памяти, прочитать модели) и защитить веса открытых
моделей — они и так открытые. Ценное у нас — сборка, приложения и
поддержка, а не веса.

## Загрузка: Secure Boot своими ключами

- На заводе прошивка (UEFI) переводится в режим настройки, в неё
  записываются **наш PK и KEK**, в `db` — наш ключ подписи и сертификат
  **Microsoft UEFI CA 2023** (и 2011, пока нужен) для option ROM карт.
  Сертификат Microsoft для Windows **не** кладём. Записать можно
  `sbctl` или автозаписью ключей systemd-boot
  (`secure-boot-enroll`) **[не проверено на нашей плате]**.
- Почему оставляем Microsoft UEFI CA: прошивки видеокарт и сетевых карт
  подписаны им; без него Джарвис может не показать картинку или не
  запустить карту. Цена: с ним может загрузиться чужой подписанный
  Microsoft загрузчик (shim других систем). Это закрывают пароль на
  прошивку и выключенная загрузка с USB — а главное, TPM: при чужом
  загрузчике меняется PCR 7, и ключ диска не откроется. Данные клиента
  остаются закрыты.
- **Лучший вариант — договориться с заводом**, чтобы наши ключи стояли в
  «заводских настройках» прошивки (AMI/Insyde это умеют): тогда «сброс
  настроек» возвращает наши ключи, а не ключи Microsoft. **[Зависит от
  завода, обсуждать на месте.]**
- Пароль на прошивку (свой на каждую коробку, хранится у нас и в
  запечатанном конверте у клиента), загрузка только с внутреннего диска.
- Подпись: UKI подписывается при сборке (`ukify`/mkosi), с ней —
  подписанная политика PCR 11 (`systemd-measure`): TPM откроет диск только
  системе, подписанной нами, в любой нашей версии — обновление не требует
  перезапечатывания.

## Система только для чтения

- `/usr` — erofs + **dm-verity**, корень хеша — внутри подписанного UKI
  (`usrhash=` в строке запуска), подпись разделов verity — нашим ключом.
- Модули ядра подписаны ключом сборки, ядро грузит только подписанные
  (`module.sig_enforce=1`, lockdown `integrity`).
- Расширения (`systemd-sysext`, драйвер NVIDIA) — тоже dm-verity и подпись.
- Контейнеры — только с нашей sigstore-подписью (`policy.json`).
- **Ключи подписи** в репозиторий и в обычные секреты Actions не кладём.
  Боевые ключи — на аппаратном ключе владельца (YubiKey / Nitrokey, PKCS#11);
  подпись выпуска — отдельный шаг с его участием. Тестовые ключи — в
  Actions для проверок. Потеря ключа = нельзя выпускать обновления: две
  копии ключа в двух сейфах **[решение владельца]**.

## Диск: LUKS2 + TPM

- Раздел данных — LUKS2. Ключ запечатан в TPM2 (`systemd-cryptenroll
  --tpm2-device=auto --tpm2-public-key=… --tpm2-pcrs=7`): открывается,
  если загрузилась **наша подписанная система** (PCR 11 по подписанной
  политике) **и** Secure Boot в нашем состоянии (PCR 7).
- **Не привязываемся к PCR 0/2** (прошивка и карты): обновление BIOS или
  замена видеокарты/диска не должны запирать данные. Это и есть «замена
  деталей не блокирует».
- По желанию — PIN к TPM (`--tpm2-with-pin`) для госсектора и юристов.
- **Ключ восстановления** (`systemd-cryptenroll --recovery-key`) —
  владельцу при первой настройке (распечатать). Депонирование у нас —
  только с его галочкой и зашифрованным.
- Важно про AMD: TPM на Strix Halo и 9950X — **встроенный в процессор
  (fTPM)**. Замена платы или процессора = новый TPM = диск сам не
  откроется, нужен ключ восстановления. Это нормально и описывается в
  гарантии. Отдельный TPM-чип на плате — спросить у завода
  **[не проверено]**. Обновление прошивки fTPM иногда сбрасывает его —
  проверить на образце.

## Замена деталей — событие, а не замок

- При каждой загрузке коробка снимает опись: серийники платы, процессора,
  дисков, памяти, видеокарты (`dmidecode`, `/sys`, `nvme id-ctrl`) и
  сравнивает с заводской.
- Отличие — запись в журнал коробки и строка нам («Коробка №… : заменён
  диск»), если канал состояния не выключен. Коробка работает дальше.
- Гарантия — по договору: вскрытие и замена своими руками — за свой счёт,
  но не блокировка.

## Нет root и shell у клиента

- В системе нет входа в консоль (нет `getty` на экранах, кроме страницы
  «Состояние» с QR), SSH выключен, пока клиент не включил поддержку, и
  пускает только по нашему сертификату.
- Всё, что клиенту нужно, — в панели и боте. Нужен «доступ программиста»
  к данным — экспорт и API «Офиса», а не root.

## USB по белому списку

- **USBGuard** (GPL-2): разрешены клавиатура, мышь, спикерфон, ИБП,
  резервный диск, флешка обновления — по классам устройств и по
  конкретным устройствам из комплекта. Новое устройство — «Разрешить?» в
  панели владельцу.
- Флешки с файлами — только чтение и только через «Загрузить документы»
  в панели, без автозапуска.

## Магазин функций

- Набор = контейнеры + манифест (что читает, что пишет, какие модели,
  для каких коробок) + наша подпись. Коробка ставит только подписанное.
- Права набора показываются до установки и проверяются «Офисом».

## Удалённая поддержка

- Headscale на нашем сервере, отдельная запись на каждую коробку, правила
  доступа: только наши ноутбуки поддержки → коробка; коробки разных
  клиентов не видят друг друга.
- Кнопка в панели и боте. Вход — SSH-сертификат на часы (подписывает наш
  удостоверяющий ключ), каждый вход — в журнал клиента и строкой ему.
- Выключено — канал остановлен полностью.

## GPLv3 и запертая система

GPLv3 (раздел 6) требует для «пользовательских продуктов» (User Products)
давать «сведения для установки» изменённой версии GPLv3-программы
**[проверено по тексту: gnu.org/licenses/gpl-3.0.html, раздел 6]**.
В обычной системе Debian GPLv3 — это bash, coreutils, GRUB и др.

Что делаем:

1. **GRUB не берём** — systemd-boot (LGPL-2.1).
2. **Путь владельца железа**: пароль прошивки — у владельца коробки
   (запечатанный конверт). С ним он может сбросить ключи Secure Boot,
   записать свои и загрузить свою систему или свою сборку нашей (рецепты
   образа и исходники GPL-программ даём по запросу). Наш TPM-ключ при этом
   данные не откроет, но у него есть ключ восстановления и копия. Значит,
   изменённые GPLv3-программы на его коробке запускать **можно** — но уже
   без нашей поддержки и гарантии на ПО, что GPLv3 прямо допускает.
3. **Исходники** всех GPL-программ версии коробки — на нашем сайте и на
   диске коробки (как решено для Paperless-ngx).
4. Коробка продаётся бизнесу, но «пользовательский продукт» определяется
   по виду товара, а не по покупателю. Мини-ПК, скорее всего, им считается
   — исходим из худшего.
5. **Перед первой продажей — заключение юриста** по пп. 2–4. Это
   **[не проверено юристом]**.

Если юрист скажет, что п. 2 недостаточно, — вынимаем GPLv3 из запертого
`/usr` (bash → dash, coreutils → uutils (MIT) или busybox (GPLv2)) и
держим GPLv3-программы (Piper, Paperless, ComfyUI) только в контейнерах,
которые клиент может заменить своими. Это +2–3 недели работы.

## Что реально, что нет

| | Реально | Нет / с оговоркой |
|---|---|---|
| Нельзя подменить систему | ✓ dm-verity + подпись | человек с паролем прошивки может поставить свою систему (это мы и разрешаем) |
| Украденный диск не прочитать | ✓ LUKS2 + TPM | украденная коробка целиком без PIN загрузится в нашу систему — нужен вход в панель; для госсектора PIN |
| Нельзя скопировать нашу сборку на другое железо | ✓ приложения подписаны и привязаны к серийнику коробки (лицензия функции) | образ диска с отключённым шифрованием прочитать можно только снимая чипы — не защищаемся |
| Веса моделей не утекут | ✗ не цель | они открытые |
| Модели и код против «выкачать через API» | частично: «Ядро» только на 127.0.0.1, наружу — через «Офис» с правами | — |
| Сертификация защиты (ФСТЭК, O‘zstandart и т. п.) | не на пилоте | см. [05-feasibility.md](05-feasibility.md) |
