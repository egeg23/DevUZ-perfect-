## Вывод

**База — Debian 13 «trixie» и свой образ на mkosi по схеме ParticleOS**
(проект systemd): systemd-boot + подписанный UKI, система только для
чтения (erofs + dm-verity), обновления A/B через `systemd-sysupdate` с
откатом, данные на LUKS2 с ключом в TPM, свежее ядро из
`trixie-backports` (сейчас 7.2), NVIDIA — открытые модули и CUDA отдельным подписанным
расширением только на Джарвисе. Почему: всё нужное для запертой системы
уже есть в systemd и работает в бою; весь путь загрузки и обновления
проверяется в виртуалке до железа; Debian разрешает своё имя («на основе
Debian») и живёт годами. Запасные пути — Kairos и Fedora bootc с печатью,
когда она станет боевой. Подробно — [01-base.md](01-base.md).

**Что реально:**

- Своя система с подписанной загрузкой, A/B, откатом, шифрованием и
  кнопкой поддержки — **реально вдвоём**, и большая часть делается **до
  прихода коробки** (8 недель в QEMU и облаке).
- Приложения коробки — **продолжение кода студии**: единое окно
  мессенджеров («Сияние Севера»), ИИ-сотрудник, первичка, КП, договоры,
  задачи, сторож, голосовые. «Ядро» (шлюз моделей) — из `lib/llm/`: наш
  код, который сейчас зовёт Claude, сможет говорить с моделью коробки без
  переделки.
- **Сложно и под вопросом**: голосовые звонки с ответом за ~1 секунду,
  узбекский голос (своего нет — записываем), картинки и видео на AMD
  (ROCm на Strix Halo сырой — медиа обещаем только на Джарвисе),
  поддержка своей системы годами.
- **Не сами**: юрист (GPLv3 для запертой системы, ввоз шифрования, запись
  звонков, имя «Джарвис»), завод (наши ключи в прошивке), сертификация.

**С чего начать** (предложение): неделя 1 из
[06-roadmap.md](06-roadmap.md) — образ Debian 13, который собирается в
GitHub и грузится в виртуалке; к концу недели 3 — подписанная загрузка,
A/B с откатом и шифрование с TPM, проверенные тестами. Параллельно
владелец заказывает образец «Про» и юриста. Первая версия функций узкая:
чат по документам, клиенты и продажи, документы, голосовые и протоколы,
сама коробка и пакет «Клиника» ([03-functions.md](03-functions.md)).

## Решения владельца, 02.11.2026

Ответ на список ниже: «1) Тебе виднее, поддерживаю твою логику. 2) код ОС —
сделай репозиторий сам, открытый или закрытый — решать тебе… 3) Не знаю,
скажи как лучше. 4) Ок. 5) Ок… 6) Согласен, но лучше изучить Гит… Ну
погнали в новой сессии тогда — неделя 1!»

1. **База** — Debian 13 + mkosi, как в плане.
2. **Репозиторий `egeg23/devuz-os` — открытый.** Почему: минуты GitHub
   Actions для открытых репозиториев бесплатны, а образ системы
   собирается и проверяется в QEMU на каждый пуш (у закрытого — 2 000
   минут в месяц на бесплатном тарифе, это несколько дней работы);
   рецепты образа не секрет, а открытость помогает с обязательствами GPL.
   Секретное — ключи подписи — в репозиторий не попадает никогда.
   Приложения «Офиса» и магазин функций, когда до них дойдём (неделя 6),
   — отдельным **закрытым** репозиторием: это наш продукт.
   Создать репозиторий сессия не может (нет права) — пустой создаёт владелец.
3. **Ключи подписи** — нужны не сразу: недели 1–7 работают на тестовых
   ключах, которые Actions создаёт и выбрасывает. К неделе 8 (заводская
   флешка) купить **два YubiKey 5** (ключ PIV, RSA-2048 — его принимают
   прошивки UEFI). Ключи создаются один раз на отключённом от сети
   компьютере, записываются в оба YubiKey, зашифрованная копия — на
   флешку в сейф; один YubiKey у владельца, второй — в другом месте (сейф,
   банковская ячейка). Подпись выпуска — с YubiKey владельца, в Actions
   боевого ключа нет. **[Поддержку PKCS#11 в `ukify`/`sbsign`/mkosi
   проверить на неделе 3.]**
4. **Облачная машина с GPU по часам** — да, на недели 5–7.
5. **Юрист** — да. Имя «Джарвис» меняем на своё созвучное сокращение,
   чтобы отсылка читалась сразу ([07-name.md](07-name.md)).
6. **Первая версия узкая**, дыры закрываем готовыми открытыми проектами
   с подходящими лицензиями (соцсети, мониторинг репутации, документы,
   PDF, презентации и др.) — отдельный поиск по GitHub параллельно неделе
   1, итог — `08-open-source.md`.

План первой недели — [week-01.md](week-01.md), проверен второй моделью
(Fable) до старта.

## Что было вынесено на решение

1. **База** — согласен ли с Debian 13 + mkosi.
2. **Где код ОС** — отдельный репозиторий (`egeg23/devuz-os`), открытый
   или закрытый. Рецепты образа можно держать открытыми (помогает с GPL),
   приложения «Офиса» — как решит владелец. Ключи подписи — ни там, ни там.
3. **Ключи подписи** — купить два аппаратных ключа (YubiKey / Nitrokey),
   где хранить вторую копию.
4. **Облачная машина с GPU по часам** для недель 5–7 (замеры NVIDIA и
   сравнение моделей на ru/uz).
5. **Юрист** — GPLv3 и «запертая» система, ввоз шифрования в Узбекистан и
   Россию, звонки, товарные знаки (имя ОС, «Джарвис»).
6. **Имя ОС** — оставить «DevUz OS» или своё ([07-name.md](07-name.md)).
7. **Первая версия** — согласен ли с узким составом и с тем, что медиа —
   только Джарвис.
8. **Депонирование ключа восстановления у нас** — предлагать клиентам или
   нет (удобно, но мы становимся хранителем ключей).
9. Из `future.md` по-прежнему: заказ образца «Про», «Джарвис» сразу или
   после пилота, кто пишет поставщикам и заводу.
