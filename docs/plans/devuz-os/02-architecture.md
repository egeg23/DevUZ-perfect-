Рабочее имя системы в плане — **DevUz OS** (так она названа на сайте,
`BOX_OS` в `content/box.ts`; варианты имени — в [07-name.md](07-name.md)).

### 0. Загрузка

- Прошивка (UEFI) с нашими ключами Secure Boot: свой PK и KEK, в `db` —
  наш ключ и сертификат Microsoft UEFI CA для «вшитых» программ карт
  (option ROM видеокарты подписан Microsoft; без него Джарвис может не
  показать картинку и не запустить карту) **[не проверено на RTX PRO 6000 —
  проверить на образце]**. Сертификат Microsoft для Windows в `db` не
  кладём. Подробно — [04-security.md](04-security.md).
- systemd-boot (LGPL, не GPLv3, в отличие от GRUB) грузит UKI. UKI —
  ядро + initrd + строка запуска + хеш корня dm-verity одним файлом с
  нашей подписью. Подменить строку запуска нельзя: она внутри подписи.
- Счёт загрузок (`boot counting`): новая версия получает 3 попытки; не
  дошла до «готов» (`boot-complete.target` после проверки служб) —
  загрузчик сам берёт прошлую.

### 1. Система

Разметка диска (`systemd-repart` при первой установке):

| Раздел | Размер (Про, 2 ТБ) | Что там |
|---|---|---|
| ESP | 1 ГБ | systemd-boot, UKI версий A и B |
| usr-A + verity-A + подпись | ~8 ГБ | система версии A, только чтение |
| usr-B + verity-B + подпись | ~8 ГБ | система версии B |
| root | остальное | LUKS2 (ключ в TPM): `/var` и `/etc` — данные клиента, контейнеры, модели |

- `/usr` — erofs + dm-verity: любое изменение байта — ошибка чтения, а не
  тихая подмена.
- `/etc` — собирается при загрузке из образа (`/usr/share/factory`) и
  наших настроек; то, что меняет панель, — в `/var/lib/devuz/…`.
- Нет `apt`, нет пакетов в работающей системе: система меняется только
  целиком, новой версией образа.
- Ядро 6.18 LTS, Mesa, прошивки (`firmware-amd-graphics`, микрокод) — в
  образе. Драйвер NVIDIA и CUDA — расширение системы (`systemd-sysext`,
  тоже с dm-verity и подписью), ставится только на Джарвис.

### 2. Службы

- **Podman** (Apache-2) без демона, юниты **quadlet** (`.container` файлы
  systemd). Каждая служба — свой контейнер, свои права, свой сторож.
  Docker не берём: лишний демон и root.
- Контейнеры — только с нашей подписью (политика `containers-policy.json`
  с sigstore-ключом): чужой образ Podman не запустит.
- Базы: **PostgreSQL** (данные приложений), **Qdrant** (Apache-2,
  поиск по документам), файлы — `/var/lib/devuz/files`.
- **Caddy** (Apache-2) — вход: `https://box.local` в сети офиса, свой
  сертификат коробки (корневой сертификат ставится на ПК сотрудников при
  настройке, или вход через имя в домене клиента).
- **Restic** (BSD-2) — копии, **Tailscale-клиент** (BSD-3) — канал
  поддержки к нашему Headscale.

### 3. Модели

| Что | Программа | Лицензия программы | Где |
|---|---|---|---|
| Чат, рассуждение | llama.cpp `llama-server` (Vulkan на AMD) | MIT | Лайт, Про |
| Чат, много людей сразу | vLLM | Apache-2 | Джарвис, Джарвис Max |
| Смена моделей в памяти | llama-swap или своё в «Ядре» | MIT | Лайт, Про |
| Голос → текст | faster-whisper | MIT | все |
| Текст → голос | Piper (GPL-3, отдельной программой), CosyVoice 3 | GPL-3 / Apache-2 | все / Про+ |
| Поиск по документам | bge-m3 + bge-reranker | MIT | все |
| Зрение, сканы, OCR | Qwen3-VL | Apache-2 | все (размер по модели) |
| Картинки | ComfyUI + Qwen-Image / Edit | GPL-3 / Apache-2 | Про (медленно), Джарвис |
| Видео | Wan 2.2 | Apache-2 | Джарвис |

Какие модели в какой коробке (оценка по объёму памяти, **[не проверено
замером]**; веса в 4-битном сжатии, MXFP4 у gpt-oss):

| Коробка | Всегда в памяти | По очереди |
|---|---|---|
| Лайт, 64 ГБ | gpt-oss-20b (~13 ГБ), Qwen3.6-35B-A3B (~20 ГБ), bge-m3, Whisper | Qwen3-VL-8B, Piper |
| Про, 128 ГБ | gpt-oss-120b (~63 ГБ), Qwen3.6-35B-A3B (~20 ГБ), bge-m3, Whisper | Qwen3-Coder-30B, Qwen3-VL, картинки |
| Джарвис, 96 ГБ GPU + ОЗУ | gpt-oss-120b в GPU | Qwen3.5-122B-A10B, Coder, VL, картинки, видео |
| Джарвис Max, 192 ГБ GPU | всё сразу | — |

Qwen3.5-122B-A10B (~70 ГБ) на Про — вместо gpt-oss-120b, а не вместе:
выбор главной модели — по итогам сравнения на русском и узбекском
(«Сравнение Claude и Qwen», раздел 6).

**Как модели ставятся.** Веса — не в образе системы (десятки гигабайт),
а отдельно: каталог `/var/lib/devuz/models`, у каждой модели наш
манифест (имя, версия, лицензия, sha256 каждого файла, для каких коробок),
подписанный нашим ключом (minisign или sigstore). На заводе модели
записываются на диск сразу — клиенту ничего качать не надо. Новая модель —
манифест из нашего канала обновлений, файлы с нашего зеркала или с
Hugging Face по закреплённой версии; коробка проверяет хеш и подпись до
первого запуска. Перед каждой новой моделью — её LICENSE (правило из
`future.md`).

### 4. «Ядро» — шлюз моделей и маршрутизатор

Своя небольшая служба на Node (без чужого бренда; в студии есть основа —
`lib/llm/route.ts` и `lib/llm/openai-compat.ts`).

- Одна точка входа для всех приложений: OpenAI-совместимый и
  Anthropic-совместимый API на `127.0.0.1`. Наш код, который зовёт
  `anthropic(site)`, работает в коробке без переделки: `openai-compat.ts`
  уже переводит запрос и ответ, включая инструменты.
- **Маршрут по задаче, а не по имени модели**: приложение просит `chat`,
  `chat-uz`, `code`, `vision`, `embed`, `stt`, `tts`, `image`; «Ядро»
  выбирает модель по таблице коробки (Лайт и Джарвис — разные).
- **Очередь с приоритетами**: живой звонок > чат с клиентом > сотрудник >
  ночные задачи. Ночные задачи (разбор звонков за день, отчёты) не мешают
  звонку.
- **Подгрузка**: на Лайт и Про модель «по очереди» поднимается по
  требованию и выгружается после простоя; на Джарвис Max всё в памяти.
- **Облако — выключено по умолчанию.** Владелец коробки может включить
  запасной путь в облако (например, Claude) для конкретной функции с
  явной надписью «данные этой функции уйдут из офиса». Иначе — никуда.
- **Учёт**: кто, какая функция, сколько токенов и времени — по образцу
  `model_usage`; виден владельцу коробки, нам — только числа, если он
  разрешил.

### 5. Наши приложения

Одно приложение «Офис» (Node, по образцу «Сияние Севера»:
`scripts/protos/syanie/app/` — node без пакетов, SQLite, ключи каналов
зашифрованы) и отдельные службы для тяжёлого (звонки, медиа, OCR).
Что переносим из кода студии, что берём открытым, что пишем — в
[03-functions.md](03-functions.md). Главное:

- **Не переносим панель студии целиком.** `app/admin` завязана на
  Supabase и на процессы студии (касания, скаут, очередь лидов). Берём
  логику модулей (первичка, ИИ-сотрудник, договоры, проверки текста), а
  экраны «Офиса» собираем заново, простыми, для клиента.
- База — PostgreSQL в коробке; для маленьких служб — SQLite.
- Сценарии автоматизаций — свой простой движок «когда → что» в «Офисе»
  для типовых сценариев (готовые, включаются галочкой) и **Activepieces CE**
  (MIT) или **Node-RED** (Apache-2) для своих сценариев клиента. n8n — нельзя
  (лицензия).

### 6. Панель и бот

- **Рабочий стол** в браузере любого ПК офиса и телефона (как приложение,
  PWA — как наша панель, `lib/admin/pwa.ts`): клиенты, задачи, чат с ИИ,
  документы, сводка дня. Языки: русский, узбекский, английский.
- **Бот коробки в Telegram** — уведомления и короткие действия (как наш
  бот студии): «🔔 новая заявка», «утренняя сводка», «✓ сделано». Вход в
  панель с телефона — код из бота (`lib/admin/app-login.ts`).
- У клиента нет терминала, root и SSH: всё, что можно настроить, — в
  панели «Настройки коробки».

## Обновления

| Что | Как | Откат |
|---|---|---|
| Система (ядро, `/usr`, драйверы) | `systemd-sysupdate`: качает версию в свободный слот A/B, проверяет подпись, перезагрузка ночью в окно, которое выбрал клиент | 3 неудачные загрузки — прошлая версия сама; кнопка «Вернуть прошлую версию» |
| Приложения (контейнеры) | новые образы с подписью, `podman auto-update` по нашему каналу | прошлый образ остаётся, сторож возвращает его, если новый не поднялся (как `devuz:previous` у сайта) |
| Модели | манифест + файлы, проверка хеша | прошлая версия модели лежит до подтверждения |
| Функции из магазина | подписанный набор (контейнер + манифест прав) | «Выключить» в панели |

- Каналы: `stable` (клиенты), `beta` (наша коробка в студии и
  согласившиеся), `dev` (тест). Сначала на нашей коробке, через неделю — всем.
- Схемы баз меняются только вперёд, с копией перед миграцией.
- Без интернета коробка работает; обновление можно принести на флешке из
  белого списка (подписанный файл).
- Где лежат обновления: не на боевом сервере сайта (правило CLAUDE.md
  про тяжёлую работу) — в хранилище файлов с CDN; собирает GitHub Actions.

## Данные и копии

- Все данные клиента — на зашифрованном разделе (LUKS2, ключ в TPM).
- **Каждую ночь** — Restic на резервный диск из комплекта (USB, свой
  ключ шифрования). По желанию — ещё и в облако клиента (S3, свой
  сервер) с ключом, которого у нас нет.
- **Копия доступна клиенту всегда**: «Скачать всё» в панели — архив
  (база в открытом виде, файлы, переписка, документы) и инструкция, как
  открыть его без коробки. Это обязательство из мягкой защиты.
- Ключ копий и ключ восстановления диска владелец получает при первой
  настройке (раздел 4): без них при поломке платы данные не вернуть.
- Проверка копий: раз в неделю коробка сама восстанавливает пробную копию
  во временный каталог и сверяет. Не вышло — строка владельцу и нам.

## Мониторинг и сторож

- Сторож по образцу `deploy/watchdog.sh` (три молчания — перезапуск, не
  помогло — один раз зовёт человека), только на systemd: `WatchdogSec`,
  `Restart=`, проверка `/health` каждой службы.
- Следит: температура, память GPU, место на диске, SMART диска, ИБП (NUT),
  ответ моделей, очередь «Ядра», копии, сертификаты, срок поддержки.
- Владельцу коробки — строки в бот и «Состояние» в панели простыми
  словами («Диск заполнен на 85%, удалим старые записи звонков?»).
- Нам — только состояние (числа и коды), без содержимого, и только если
  клиент не выключил. Выключил — видим лишь «коробка жива».

## Удалённая поддержка

- Свой **Headscale** (BSD-3) на нашем сервере; в коробке — клиент
  Tailscale. Каждая коробка — отдельный пользователь с правилами доступа:
  коробки разных клиентов друг друга не видят.
- **Кнопка «Доступ поддержки: вкл / выкл»** в панели и в боте. Выключено —
  клиент Tailscale остановлен, к коробке не зайти никак. Включено — мы
  заходим по SSH с коротким сертификатом (часы), каждый вход — в журнал
  клиента и строка ему в бот: «Поддержка DevUz зашла в 14:02».
- Без включения — только сторож с числами (если разрешён).

## Первая настройка «из коробки»

Цель — 20–30 минут без специалиста. Клиент подключает питание, сеть и
ИБП.

1. Коробка грузится, на корпусе/экране (если подключён монитор) — QR и
   адрес. Без монитора — своя Wi-Fi сеть `DevUz-XXXX` на время настройки
   или адрес `http://devuz.local` в сети офиса.
2. Язык → название компании → отрасль (пакет: клиника, юристы, розница…).
3. **Владелец**: Telegram — привязка через бота коробки кодом (как
   `app-login`), без паролей.
4. **Ключи**: коробка показывает ключ восстановления диска и ключ копий,
   просит распечатать или сохранить и проверяет, что сохранили (ввести 4
   знака). По желанию — депонировать у нас зашифрованным (отдельная галочка).
5. Сеть: адрес в офисе, имя `box.<домен клиента>` или `box.local`.
6. Резервный диск: подключить — проверка — первая копия.
7. Каналы: Telegram-бот компании (токен), Wazzup (ключ), почта, SIP
   оператора — каждое поле с подсказкой «где взять» (как «Подключения» у
   «Сияние Севера»). Можно пропустить.
8. Документы компании: перетащить папку — коробка проиндексирует ночью.
9. Сотрудники: имена и Telegram — каждому ссылка-приглашение.
10. Проверка: короткий звонок/сообщение самому себе, пробный вопрос ИИ.

Всё, что пропущено, остаётся карточками «Осталось подключить» на сводке.

## Сеть филиалов

- Каждый филиал — своя коробка (данные филиала — у него), главная
  коробка — «головная».
- Связь между коробками одного клиента — через тот же Headscale, в
  отдельной сети клиента (WireGuard, шифрование от коробки к коробке; наш
  сервер видит только зашифрованный поток, если работает как ретранслятор).
- Что общее: справочники (услуги, цены, шаблоны документов), сводка
  руководителю по всем филиалам, единый поиск по разрешённым папкам,
  передача клиента/звонка в другой филиал. Что не общее: переписка и
  документы филиала — по правам.
- Тяжёлое (видео, большие модели) филиал может просить у головной
  коробки (Джарвис в главном офисе, Лайт в филиалах) — через «Ядро».
  Это оценка, **[не проверено]**: задержка канала между городами.
- Вторая коробка в том же офисе — запасная: копии и при поломке главной
  поднимает её роль (позже, не в первой версии).
