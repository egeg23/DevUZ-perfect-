# 8. Готовые открытые проекты — чем закрываем дыры

Задача владельца, 02.11.2026: «лучше изучить Гит, возможно есть открытые
истории которые помогут сэкономить время и токены, но функционально
заполнять дыры. К примеру — ведение соцсетей, мониторинг репутации в сети,
работа с документами, пдф и презентациями и тд».

Это **план**, кода нет. Всё ниже проверено 02.11.2026: лицензия — по самому
файлу `LICENSE` (и папкам `ee/`, `enterprise/`, `premium/`, `proprietary/`)
в репозитории, у моделей — по карточке весов отдельно от кода; звёзды и
последний коммит — по поиску GitHub в тот же день. Что не сверено —
**[не проверено]**.

## Правила отбора

- **Берём как есть**: MIT, Apache-2.0, BSD, MPL-2.0, LGPL, ISC, у весов —
  ещё CC-BY-4.0 (нужна только строка «авторы такие-то» в «О системе»).
- **GPL / AGPL — только отдельной службой** в своём контейнере, исходники
  нашей версии — в коробке и на сайте (см. [04-security.md](04-security.md),
  «GPLv3 и запертая система»). AGPL ещё и сетевое условие: пользователи
  коробки (сотрудники клиента) должны мочь получить исходники — ссылка
  «Исходный код» в «О системе». Наш код с AGPL-программой говорит только по
  сети (API), в один процесс её не вшиваем.
- **Не берём**: SSPL, BSL, «Sustainable Use», Commons Clause, Elastic
  License, «некоммерческие» лицензии, open core, где нужное лежит в платной
  папке, лимиты пользователей для своего бренда, запреты по странам.
- **Бренд**: в интерфейсе — «DevUz OS» и наши названия разделов; авторские
  строки и лицензии — в «О системе». Проект, который требует свой логотип в
  интерфейсе, помечен.
- **Без интернета**: проект работает в коробке без облака автора.
  Соцсети и почта сами по себе ходят в интернет — это нормально, но через
  свою программу, а не через сервис автора.

### Новые сценарии-кандидаты

Дыры, которых в [03-functions.md](03-functions.md) не было, — кандидаты
С-46…С-54. В 45 сценариев первой разметки не входят, пока владелец не
скажет, в какую волну их ставить.

- **С-46. Соцсети по плану** (маркетинг; все): календарь постов на неделю,
  текст и картинка — из «Студии», согласование руководителем, публикация в
  Instagram, Telegram, TikTok, VK по расписанию. Postiz [открытое], экран и
  связка [с нуля].
- **С-47. Репутация** (руководитель, маркетинг; все): новые отзывы на
  картах, упоминания в Telegram-каналах и новостях → «хорошо / плохо /
  жалоба», черновик ответа, жалоба — строкой сразу. changedetection.io +
  RSSHub [открытое], разбор моделью и сводка [с нуля].
- **С-48. Действия с PDF и Office** (все; все): объединить, разрезать,
  сжать, сделать поиск по скану, Word → PDF, править документ в браузере.
  OCRmyPDF, Gotenberg, Collabora [открытое].
- **С-49. Презентация из текста или КП** (продажи, маркетинг; П, Д, ДМ):
  «сделай презентацию по этому КП в нашем шаблоне» → правящийся PPTX.
  Presenton [открытое].
- **С-50. Договор на подпись по ссылке** (продажи; все): договор из С-17 →
  ссылка клиенту → подписанный PDF с журналом в карточке. DocuSeal
  [открытое]; ЭЦП E-IMZO / КЭП — [с нуля], после юриста.
- **С-51. Запись онлайн к мастеру** (салоны, сервис; все): страница записи
  с услугами и мастерами, запись — в «Офис». Запись «Сияния Севера»
  [перенос] или Easy!Appointments [открытое].
- **С-52. Регламенты компании** (руководитель, HR; все): книги и страницы
  регламентов с правами; чат-помощник отвечает по ним. BookStack
  [открытое].
- **С-53. Почта в «Офисе»** (все; все): письма клиентов из ящика компании
  по IMAP — в единое окно, ответ оттуда же; свой почтовый сервер —
  Stalwart, по желанию. [с нуля] + Stalwart [открытое].
- **С-54. Склад** (розница, мебель; все): остатки, приход, расход; «меньше
  5 — закупщику». InvenTree [открытое], связка [с нуля].

## Что экономим

Грубая оценка «сколько не пишем с нуля» (в неделях работы вдвоём, по
опыту студии; точнее — после первого запуска каждого):

| Дыра | Свою часть пишем | Не пишем благодаря проекту |
|---|---|---|
| Соцсети | экран «Публикации», связка со «Студией» — 1–2 нед. | календарь, очереди, 10+ площадок — 8–12 нед. и вечная поддержка API |
| Репутация | правила, сводка, экран — 1–2 нед. | слежение за страницами, ленты — 4–6 нед. |
| PDF и OCR | кнопки в «Офисе» — 1 нед. | OCR, конвертация Office — невозможно самим в разумный срок |
| Правка Office в браузере | встраивание — 1 нед. | редактор — невозможно самим |
| Презентации | кнопка, шаблоны — 1 нед. | генерация и правящийся PPTX — 4–6 нед. |
| Таблицы | права и запрос — 1–2 нед. | движок таблиц — 6+ нед. |
| Подпись | связка с договором — 1 нед. | подпись, журнал, PDF — 4 нед. |
| База знаний | связка с чатом — 0,5 нед. | редактор и права — 3–4 нед. |
| Склад | связка с CRM — 1 нед. | склад — 6+ нед. |
| Музыка, 3D, разделение говорящих | обёртки в «Ядре» — по 0,5–1 нед. | модели — невозможно самим |
| Агент в браузере | защита и сценарий — 1 нед. | агент — 3–4 нед. |

Итого: своей работы — около 12–16 недель вдвоём на все дыры вместо
~50+ недель «с нуля» плюс то, что сами не сделать вовсе (OCR, редактор
Office, модели). Цифры — оценка, не замер.
