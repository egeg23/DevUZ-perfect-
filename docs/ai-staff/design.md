# ИИ-сотрудники: проект первой версии

Продукт: **ИИ-менеджер продаж по подписке** для малого и среднего бизнеса
Узбекистана. Отвечает покупателям клиента 24/7 в Telegram и в виджете на сайте,
на русском и узбекском (латиница), по прайсу и базе знаний клиента; выясняет,
что нужно, берёт контакт и передаёт заявку человеку клиента в Telegram и в
кабинет. Основание — `docs/ai-staff/research.md`.

## 1. Что в первой версии и что нет

| Есть | Нет (задел) |
|---|---|
| Одна роль — `sales` (менеджер продаж) | SMM/контент, аналитик: только значения роли в базе (`ai_employees.role`) |
| Каналы: Telegram Business, свой бот клиента по токену, виджет на сайт | Instagram Direct, WhatsApp, amoCRM/Bitrix24 |
| Только входящие: ИИ первым никому не пишет | Дожим, рассылки |
| Кабинет клиента ru/uz: вход через Telegram, мастер, база знаний, проверка на себе, разговоры, заявки, расход, тариф, команда | Голосовые (распознавание речи), фото прайса |
| Оплата счётом, отметка оплаты владельцем студии в панели | Click / Payme: заделом (`lib/ai-staff/plans.ts`, список для мерчанта — `pilot.md`) |
| Раздел владельца в панели `/admin/ai-staff` (ru/uz/pl, инструкция) | — |
| Публичная страница `/ru/ai-sotrudnik`, `/uz/ai-sotrudnik` с живым демо | Остальные языки сайта |

## 2. Механики, взятые у готовых решений

Из `research.md`, раздел 2.3 — что берём и в каком виде:

1. **Telegram Business** (нет ни у кого из местных): владелец подключает
   нашего бота в «Настройки → Telegram для бизнеса → Чат-боты» и ИИ отвечает
   от его имени в его личном Telegram. Требует Telegram Premium у владельца.
2. **Обучение за минуты** (Chatbase, Fin): база знаний текстом или с сайта
   клиента — сервер открывает сайт, недорогая модель раскладывает текст на
   пункты (цены, услуги, часы, адрес, доставка, вопросы-ответы).
3. **Передача человеку с карточкой** (Jivo, нейросотрудники amoCRM): имя,
   контакт, что нужно, бюджет, срочность, короткое резюме и номер заявки —
   в Telegram всем людям клиента с галочкой «получать заявки», кнопка «Беру».
4. **Человек перехватывает разговор** (Intercom): владелец сам написал в чат
   Business — ИИ молчит в этом чате 12 часов; в кабинете — «Вести самому» /
   «Вернуть ИИ».
5. **Проверка на себе до подключения** (Tidio, Chatbase): тестовый чат в
   кабинете на той же базе и тем же движком.
6. **Режим работы** (Jivo): «всегда» или «только в нерабочее время»;
   ночь и выходные — главное обещание.
7. **Пакет диалогов в сумах + пробный период** (Jivo, Salebot), а не плата
   за решённый вопрос (Fin) — понятнее малому бизнесу Узбекистана.
8. **Отчёт владельцу клиента** — в кабинете: диалоги, заявки, скорость
   ответа, «вне рабочего времени»; вопросы, на которые ИИ не знал ответа.
9. **Честность**: первое сообщение ИИ говорит, что отвечает ИИ-помощник
   компании (ст. 46-2 ч. 2 КоАО, `legal.md`); на вопрос «вы бот?» — да.

## 3. Данные (миграция `0100_ai_staff`)

Все таблицы с префиксом `ai_`. RLS включён, политик нет — как во всей базе:
читает и пишет только сервер по сервисному ключу.

| Таблица | Что хранит |
|---|---|
| `ai_settings` | Флаг включения сервиса (`enabled`) и прочие настройки сервиса |
| `ai_tenants` | Клиент: название, ниша, язык, тариф, пробный срок, оплачено до, статус, режим работы, часы |
| `ai_members` | Люди клиента: Telegram id, имя, роль (`owner`/`manager`), получать заявки |
| `ai_employees` | ИИ-сотрудник клиента: роль (`sales`, задел `smm`, `analyst`), имя, приветствие, тон, модель (`standard`/`premium`) |
| `ai_knowledge` | База знаний: вид пункта, заголовок, текст, откуда (`text`/`site`) |
| `ai_channels` | Каналы: вид, состояние, внешний id (business_connection_id, id бота), ключ виджета, токен бота (зашифрован) |
| `ai_conversations` | Разговоры: канал, чат, покупатель, язык, кто ведёт (`ai`/`human`), сообщения, счётчики, заявка |
| `ai_leads` | Заявки: номер, имя, контакт, что нужно, бюджет, срочность, резюме, статус, кто взял |
| `ai_payments` | Оплаты, отмеченные руками: сумма, месяцев, способ, кто отметил |
| `ai_login_tokens`, `ai_sessions` | Вход в кабинет: одноразовая ссылка из бота и сессия; в базе только хеши |

**Изоляция клиентов.** Любой запрос к таблице клиента идёт через
`lib/ai-staff/store.ts`, и каждый из них фильтрует по `tenant_id`, который
берётся из сессии кабинета, из канала или из ключа виджета — никогда из
тела запроса. Тест `tests/ai-staff-isolation.test.ts` читает код и не
пропускает запрос к таблице `ai_*` без `tenant_id` вне списка исключений
(вход, поиск канала по внешнему id).

**Секреты.** Токен бота клиента хранится зашифрованным (AES-256-GCM, ключ
`AI_STAFF_KEY` в `.env` или хранилище секретов). Токен нашего бота —
`AI_STAFF_BOT_TOKEN`, секрет вебхука — `AI_STAFF_WEBHOOK_SECRET`.

## 4. Каналы

```
Покупатель ─┬─ Telegram Business ──► @наш_бот (business_message) ──► /api/ai-staff/tg/<секрет>
            ├─ свой бот клиента ───► /api/ai-staff/bot/<id канала>/<секрет>
            └─ виджет на сайте ────► /api/ai-staff/widget (POST, ключ виджета)
                                         │
                                         ▼
                             lib/ai-staff/engine.ts (один ход разговора)
                                         │
                         ┌───────────────┴───────────────┐
                         ▼                               ▼
                 ответ покупателю               заявка: ai_leads + Telegram
                                                людям клиента (наш бот) + кабинет
```

- **Telegram Business.** `business_connection` — бот подключён: ищем клиента
  по Telegram id владельца (`ai_members`), заводим или обновляем канал.
  Неизвестный человек — бот отвечает ему, как зарегистрироваться.
  `business_message` от покупателя — ход движка, ответ `sendMessage` с
  `business_connection_id`. Сообщение от самого владельца — перехват на 12
  часов. Отвечать можно, только пока покупатель писал за последние 24 часа
  (`can_reply`) — для входящих это не мешает.
- **Свой бот клиента.** Клиент вставляет токен из BotFather; сервер
  проверяет его (`getMe`), ставит вебхук с секретом и хранит токен
  зашифрованным. Отключить — снять вебхук.
- **Виджет.** Одна строка `<script src="https://devuz.studio/api/ai-staff/widget.js?k=КЛЮЧ" async></script>`.
  Ключ публичный, он определяет клиента; лимиты по IP и по клиенту.
  Переписка хранится на сервере по случайному id посетителя.

ИИ первым не пишет нигде: ход движка запускается только входящим.

## 5. Движок

`lib/ai-staff/engine.ts` — отдельный слой, движок первички студии
(`lib/qualify/engine.ts`) не меняется. Берём из него проверенные части:

- `ReplyGuard`-логику — `findSelfTalk` из `lib/qualify/self-talk.ts`: имя
  поставщика модели или оправдания не уходят покупателю;
- `inventedNumbers` из `lib/admin/outreach.ts`: в ответе нет чисел и цен,
  которых нет в базе знаний клиента или в словах покупателя; промах —
  повтор с замечанием, второй промах — безопасная фраза «уточню у
  менеджера» и пометка в разговоре;
- `contactIn` из `lib/qualify/contact.ts`: контакт покупателя из переписки
  кодом, если модель его не переписала;
- прощание с номером заявки — шаблоном кода (как `lib/qualify/closing.ts`),
  без второго запроса к модели.

Промпт собирается из базы знаний клиента и кэшируется (база неизменна между
репликами). Инструмент `hand_off` (строгая схема): имя, контакт, что нужно,
бюджет, срочность, резюме, причина передачи. Модель по умолчанию —
`AI_STAFF_MODEL` (Sonnet, `claude-sonnet-5`), тариф «Про» —
`AI_STAFF_PREMIUM_MODEL` (Opus, `claude-opus-5`); разбор сайта —
`AI_STAFF_IMPORT_MODEL` (Haiku). Каждый вызов — `anthropic("saas-<id клиента>")`,
поэтому себестоимость клиента видна в `model_usage` по метке.

## 6. Тарифы и лимиты

Диалог — разговор с покупателем, в котором ИИ ответил хотя бы раз за
календарный месяц. Себестоимость (оценка, проверяется по `model_usage`):
реплика Sonnet ≈ $0,006–0,01, диалог из 5–8 реплик ≈ $0,05. Первый замер
на боевом сервере 10.10.2026 (демо-клиент, 2 диалога, 4 ответа и один
повтор после проверки): 5 вызовов Sonnet, $0,019 — около $0,01 за диалог,
системный промпт с базой знаний читается из кэша.

| Тариф | Цена в месяц | Диалогов | Каналы | Модель |
|---|---|---|---|---|
| Пробный | 0, 14 дней | 100 | все | Sonnet |
| Старт | 490 000 сум | 300 | 1 канал | Sonnet |
| Бизнес | 990 000 сум | 1 000 | все | Sonnet |
| Про | 2 490 000 сум | 1 500 | все | Opus |

Лимит исчерпан или срок кончился — ИИ молчит, покупатель получает короткую
фразу «менеджер ответит», люди клиента — сообщение, владелец студии видит
это в панели. Оплата — счётом и отметкой в панели (`ai_payments`,
продлевает `paid_until`). Click и Payme — следующим шагом, когда владелец
заведёт мерчант-аккаунты (что нужно — `pilot.md`).

## 7. Кабинет клиента (`/cabinet`, ru/uz)

- Вход: в нашем боте `/start` → ссылка входа на 15 минут → кука сессии
  (7 дней). Регистрация — тот же `/start` с кнопкой «Создать кабинет».
- Разделы: «Обзор» (статус, срок, диалоги из лимита, заявки, скорость
  ответа), «Настройка» (мастер: компания → база знаний → канал → проверка),
  «База знаний», «Каналы», «Проверить на себе», «Разговоры», «Заявки»,
  «Команда» (ссылка-приглашение для менеджеров), «Тариф».
- Язык — переключатель RU / UZ, словарь `content/ai-staff/cabinet.ts`.

## 8. Включение и безопасность выкатки

- Сервис выключен, пока в `ai_settings` нет `enabled = true`: маршруты
  `/api/ai-staff/*` и `/cabinet` отвечают 404, публичная страница — 404.
- Существующие чат сайта, бот студии, касания и автопрогон не меняются:
  новый код живёт в `lib/ai-staff`, `app/api/ai-staff`, `app/cabinet`.
- Тяжёлого на сервере нет: разбор сайта клиента — один запрос страницы и
  один вызов недорогой модели по нажатию клиента.

## 9. Переменные окружения

| Переменная | Зачем |
|---|---|
| `AI_STAFF_BOT_TOKEN` | Токен нашего бота сервиса (BotFather, включить Business Mode) |
| `AI_STAFF_BOT_USERNAME` | Имя бота без @ — для ссылок в кабинете |
| `AI_STAFF_WEBHOOK_SECRET` | Секрет вебхука нашего бота (любая длинная случайная строка) |
| `AI_STAFF_KEY` | Ключ шифрования токенов ботов клиентов (32 байта, base64) |
| `AI_STAFF_MODEL`, `AI_STAFF_PREMIUM_MODEL`, `AI_STAFF_IMPORT_MODEL` | Модели (по умолчанию Sonnet, Opus, Haiku) |

Все читаются через `appSecret` — их можно положить и в `.env`, и в
хранилище секретов Supabase.
